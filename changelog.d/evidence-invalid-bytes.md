### Fixed
- The audit log (`~/.zn/evidence.jsonl`) is now checked for damage before anything is added to it. A log with unreadable bytes or a cut-off last line is reported as corrupted, with the line number, by `evidence --verify` (non-zero exit), `evidence` and `evidence --export`, instead of failing with a Python error. A damaged log is never used to start a new chain: the event is not written, a warning is shown (the first time, then every 5 minutes), and your command or agent carries on as usual. To recover, move the damaged file aside (`mv ~/.zn/evidence.jsonl ~/.zn/evidence.damaged.jsonl`; on Windows `move %USERPROFILE%\.zn\evidence.jsonl %USERPROFILE%\.zn\evidence.damaged.jsonl`): the next event starts a new chain and the old file stays for review. An empty or missing log still starts a fresh chain. The Node and Python versions now read the log the same way, so a log with a byte-order mark or non-breaking spaces is reported the same by both.
