### Security
- The Python `check_command` and the destructive-command check in Node.js now read shell code nested up to three levels deep (`sh -c "sh -c ..."`, `eval`, backticks) and refuse anything deeper instead of skipping it. A dangerous command wrapped in four or more shells was allowed before; it is now refused.
- The Python `check_command`, `evaluate` and the LlamaIndex `check_query` raise `TypeError` for input that is not text instead of allowing it unread. `bytes` are read as UTF-8 and a LlamaIndex `QueryBundle` is read through its `query_str`.
- The Python `sanitize_tool_result` masks secrets in `bytes`, in the attributes of objects and in the text form of objects, not only in strings, lists and dicts.
- The Python `check_tool_result` blocks a result holding an object that cannot be read (rule `type:unscannable`) instead of leaving that part out.
- The OpenAI Agents guardrail blocks a tool call whose `tool_arguments` is missing, instead of allowing it unchecked.
- A generator guarded with `@guard` now has its return value checked and masked, like the values it yields.
- The Python `sanitize_tool_result` and `@guard(mask_secrets=True)` now read the attributes of objects: a result holding an object that refers back to itself or to a parent raises `SanitizeLimitError` (rule `size:nesting`) and is blocked, where it used to be returned unmasked. An object that cannot be copied (or whose copy is itself) comes back as a dict of its masked attributes, and an object whose attributes or text form cannot be read raises `SanitizeLimitError` (rule `type:unscannable`) instead of passing through.
