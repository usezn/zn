### Security
- The Python `evaluate` and the LlamaIndex `check_query` raise `TypeError` for input that is not text instead of allowing it unread. `bytes` are read as UTF-8 and a LlamaIndex `QueryBundle` is read through its `query_str`.
- The Python `sanitize_tool_result` masks secrets in `bytes`, in the attributes of objects and in the text form of standard-library objects (an exception, for example), not only in strings, lists and dicts.
- The Python `check_tool_result` blocks a result holding an object that cannot be read (rule `type:unscannable`) instead of leaving that part out.
- The OpenAI Agents guardrail blocks a tool call whose `tool_arguments` is missing, instead of allowing it unchecked.
- A generator guarded with `@guard` now has its return value checked and masked, like the values it yields.
- The Python `sanitize_tool_result` and `@guard(mask_secrets=True)` now read the attributes of objects: a result holding an object that refers back to itself or to a parent raises `SanitizeLimitError` (rule `size:nesting`) and is blocked, where it used to be returned unmasked. When an attribute holds a secret, the masked attributes go into a new blank instance of the same class (the class's own code is not run and the original is not changed), or into a dict when no such instance can be made, and an object whose attributes or text form cannot be read raises `SanitizeLimitError` (rule `type:unscannable`) instead of passing through.
- A tool result holding an object whose own class shows values through properties, `__getattr__` or `__getattribute__` is now refused instead of passed through unread: the Python `sanitize_tool_result` raises `SanitizeLimitError` and `check_tool_result` blocks it (rule `type:unscannable`), and the Node.js result check of `guardTool` blocks a class instance with getters. A credential or an injection reachable only through such a property was let through before. Classes of the standard library, pydantic, attrs, msgspec, LangChain and LlamaIndex are read as before. Files and streams follow the same rule: a standard-library stream (`io.StringIO`, an open file, `sys.stdout`, the stream of a `logging` handler) is still checked by its name only, but a subclass of one (of `io.IOBase` or `io.StringIO`, for example) that adds a property of its own is now refused by both functions; `check_tool_result` used to allow it.
- The Node.js result check of `guardTool` now also blocks (rule `type:unscannable`) a getter or setter anywhere in the result, listed or not, on an object or inside an array, a `Set` or a `Map`, a `Proxy`, and a prototype that only claims to be a built-in one; built-in prototypes are recognized by identity. Nothing in the result is read through its code: the check reads a plain-data copy, and `maskSecrets` masks that same copy, so a getter can no longer show safe text to the check and other text afterwards. In Python, a class is trusted only when the module it names really holds it (setting `__module__` to a trusted package is no longer enough), a subclass of `dict` or `list` with properties and a class that sets `__class__` are refused the same way, and the check no longer asks an object for `__class__` before refusing it.
- What `guardTool` returns with `checkResult` can no longer turn into text that was not checked. Functions are never treated as data: the checked copy leaves out function properties (a function inside an array becomes `undefined`), so a `toJSON`, `toString`, `valueOf`, `Symbol.toPrimitive`, `then` or `util.inspect.custom` hook cannot run after the check. With `maskSecrets`, the masked copy holds no functions (the same holds for `sanitizeToolResult`). A typed array or `Buffer` with such a hook is blocked (rule `type:unscannable`). The href of a `URL` is now checked, a `String` object is checked as one string, and a thenable returned by a sync tool is settled as a real promise, so its value is checked too.
- Behaviour change: with `checkResult`, `guardTool` in Node.js now always returns the plain-data copy that was checked instead of the object the tool returned (strings, numbers, booleans, `null`, `undefined` and bigints come back as they are). Class instances come back as plain objects of their listed values, without their methods; arrays, `Map`, `Set`, `Date`, `URL`, typed arrays and `Buffer` come back as new values of the same built-in kind; an `Error` comes back as `{ name, message, cause, errors }` (its listed values included, its stack left out), a `RegExp` as its text (`/source/flags`), an `ArrayBuffer` or `DataView` as a copy of its bytes, and a function as `undefined`. So `JSON.stringify`, `String()`, a template literal, `util.inspect` or `Object.prototype.toString` can only show checked text. The message, cause and errors of an `Error`, the source of a `RegExp`, the bytes of an `ArrayBuffer` or `DataView` and the description of a `Symbol` are now checked. A result is also blocked (rule `type:unscannable`) when, since zn-gate was loaded, a built-in method or getter that the check or the copy relies on was replaced or removed (on `Object.prototype`, `Array.prototype`, `String.prototype`, `RegExp.prototype`, `Set.prototype`, `Map.prototype`, the built-in iterators, `Object`, `Array`, `JSON`, `Reflect`, or a prototype the copy uses such as `Date.prototype`), a global such as `JSON` was replaced, or such a prototype gained a `toJSON`, `toString`, `valueOf`, `toISOString`, `then`, `Symbol.toPrimitive`, `Symbol.toStringTag`, `Symbol.iterator`, `util.inspect.custom` hook, or any other key (string or symbol) that was not there when zn-gate was loaded, since the copy inherits it and the tool could read it unchecked. Load polyfills before zn-gate. The check copies and reads the result only with built-in functions it took when it was loaded (`Set.prototype.add`, `Map.prototype.set`, `Array.prototype.push`, the typed array getters, a UTF-8 decoder for the bytes of an `ArrayBuffer`, `DataView` or `Buffer`...), so a replaced built-in can no longer add text to the copy that was not checked.
- The Python `check_tool_result` and `sanitize_tool_result` now refuse (rule `type:unscannable`) a result holding an object whose class, outside the standard library and the trusted packages, defines its own `__str__`, `__repr__` or `__format__`: `str()`, `repr()`, `format()` or a log line of it could show text that was never checked, so `@guard(check_result=True)` no longer returns it. The `__repr__` that `dataclasses` and `namedtuple` write and the methods of `Enum` are not counted, so dataclasses, named tuples and enums pass as before; a generated `__repr__` is recognized by comparing its code and closure with what those helpers write, not by a file name or a marker that any class can set. Behaviour change: an attrs class with the `__repr__` that attrs writes is refused like any class with a `__repr__` of its own, because nothing that a class cannot also set tells that method apart from a hand-written one (and a per-attribute `repr` callable runs code of its own); declare the class with `repr=False`, or return its data as a dict. The arguments, cause and context of an exception in a result are now checked too. In Python, a tool result holding a subclass of `str`, `bytes`, a number, `list`, `tuple`, `dict` or `set` that redefines how it is read or turned into text (`__str__`, `__repr__`, `__iter__`, `items`, `keys`, `__getitem__`...) is now refused (rule `type:unscannable`): `str()`, `dict()` or a framework could show other text than the one the check read. Subclasses that only add methods of their own, and `namedtuple`, `Enum`, `OrderedDict` and `defaultdict` values, pass as before.
- The Node.js argument check (`checkToolCall`, and `guardTool` before it runs the tool) now reads the arguments only with built-in functions taken when zn-gate was loaded, never through an iterator or a method of the arguments, and blocks them (rule `type:unscannable`) when a built-in that the check or the rules rely on (`Object.entries`, `Object.keys`, `Array.prototype[Symbol.iterator]`, `String.prototype.toLowerCase`...) was replaced, before the arguments are read or while a getter of the arguments runs. A replaced `Object.entries` could hide an argument from the check before, and the tool then ran. An array whose own iterator lists other values, or a `Set` or `Map` subclass with its own iterator, is read by its real contents; the bytes of an `ArrayBuffer` or `DataView` (as UTF-8) and a `String` object (as one string) are now checked too. `guardTool` with `maskSecrets` blocks the result when such a built-in was replaced, instead of returning it masked through it.
- Behaviour change: `guardTool` in Node.js now runs the tool with the plain-data copy of the arguments that was checked, not with the objects the caller passed, and `checkToolCall` reads the same copy. A getter or a `Proxy` could show safe text to the check and other text to the tool before; arguments holding a getter, a setter or a `Proxy` anywhere (a `Proxy` of a `Set` that hides its entries included) are now blocked (rule `type:unscannable`), and changing an argument after the call starts no longer changes what the tool reads. Class instances arrive as plain objects of their listed values, without their methods; arrays, `Map`, `Set`, `Date`, `URL`, typed arrays and `Buffer` as new values of the same kind; functions (callbacks) as they are. With `checkArgs: false` the tool gets the arguments as they are.
- The Python result checks no longer remember a class between calls: a class that gains a `__str__`, `__repr__` or `__format__`, a property or an attribute hook after a first check (on itself, on a parent, or by a change of `__bases__`) is refused from the next check on, where a first check that allowed it was reused before.
- Node.js `guardTool` and `checkToolCall` now block (rule `type:unscannable`) arguments holding an object or a function with its own `toJSON`, `toString`, `valueOf`, `toISOString`, `then`, `Symbol.toPrimitive` or `util.inspect.custom`, or a function that inherits one from a class it extends, or a `Proxy` of a function: the copy passed to the tool keeps functions, so such a hook would run when the tool serializes the arguments and could produce text that was never checked. Callbacks passed as arguments, or under any other key, still reach the tool as they are.
- A sync tool wrapped by `guardTool` with `checkResult` whose result has a `then` getter, or is a `Proxy`, is now blocked without running that code; a real promise or a plain thenable is still settled and its value checked.
- The Python result checks trust a reading method of a `list`, `dict`, `str` or other built-in subclass only when it is, by identity, the method of the same name of a standard-library class (as `Enum` copies) or the `__repr__` or `_asdict` that `namedtuple` writes. The module name a function carries is no longer trusted, since any code can set it. `IntEnum` values now pass the result check.
- The Python `sanitize_tool_result(tool_name, content)` with content that is not a string now checks the content before writing it as JSON text, and runs no `__str__` or `__repr__` of its own classes, of a metaclass or of the object behind a bound method: such content is refused (rule `type:unscannable`) without that code running. A result that only names the module of an agent framework's run context is now checked like any other object, and a class with its own `__fspath__` counts as a custom text form.
- The Python `sanitize_tool_result` now runs the same screen as `check_tool_result` on every value before it reads it: a subclass of `list` or `dict` that redefines `__iter__`, `__len__` or `items` is refused (rule `type:unscannable`) without that code running, where its code could run and hide content. When an object holds a secret, its masked copy is now built without `copy.copy`, `__new__`, `__init__` or `__setattr__` of the object's class, so a `__copy__` or `__reduce__` of the output never runs. Class attributes and slots are read through the slots of `type`, so a metaclass hook cannot run while a result is screened. A subclass of `bytes` is refused instead of passing unmasked.
- The Python `evaluate` and `check_command` decide whether the input is text by its real type, not by `isinstance()`: an object that fakes `__class__` as `str` raises `TypeError`, a `__bytes__` of an object is never called (a subclass of `bytes` raises `TypeError`), and a subclass of `str` is read without running its code. The LlamaIndex `check_query` only reads a real `QueryBundle` (from its stored `query_str`, without running properties); any other object that is not text raises `TypeError`.
- The Python argument check (`check_tool_call`) now refuses (rule `type:unscannable`) a `list`, `dict` or other built-in subclass that redefines how it is read, without running that code, and a direct call blocks arguments holding an object whose properties or attribute hooks cannot be read; the `@guard` decorator keeps reading application objects such as clients and sessions leniently. Agent-framework run contexts are skipped only when their class really is the one that the framework module holds, so an object that only carries such a module and class name is checked like any other argument.
- The Python result and argument checks compare types by identity and read mappings, iterators, paths and files from the class itself, so a metaclass (`__eq__`, `__hash__`) or an ABC registry hook of the output never runs while it is screened. Dict keys are screened before anything asks them for their class, and an object whose `__dict__` holds a key that is not a `str` is refused instead of turned into text.
- The Python argument check now refuses (rule `type:unscannable`) a mapping of its own (a class that inherits from or is registered with `collections.abc.Mapping`) without calling its `items()`, which could hide values from the scan. Inside an application object passed to `@guard` (such as a `requests.Session`) such a mapping is read from the attributes it stores, never through its own `items()` or iteration. `dict` (and its subclasses that do not redefine reading), `types.MappingProxyType` and the mappings of the standard library are read as before. A `UserDict`, `ChainMap` or `types.MappingProxyType` is read from the mapping it holds, never through its own `items()`, so one that wraps a mapping of its own is refused too.
