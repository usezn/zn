### Added
- Optional check of the packages your agent installs by name (`npm install`, `pnpm add`, `yarn add`, `bun add`, `pip install`, `uv add`, `pipx install`). It is off by default and never blocks a command: with `hooks.packageInstallCheck` set to `"offline"` in `~/.zn/config.json` (or `ZN_PACKAGE_CHECK=offline`), your agent asks before it installs a name that looks like a well-known package (one letter off, two letters swapped, a look-alike character, other separators, or an npm scope that imitates a well-known one), using a list that ships with zn-gate and no network. With `"online"` (config file only), zn-gate also asks, for a plain install only (a command made only of install words, names and a closed list of switches), the public npm or PyPI registry, with only the package name, whether the name exists and is not brand new, and asks when it does not exist or was first published less than 14 days ago (`hooks.packageInstallNewDays`). Names you trust go in `hooks.packageInstallAllow`. Agents that cannot show a question (Codex CLI, OpenCode, Gemini CLI) run the command, and every finding is written to the decision log. See [Packages your agent installs](docs/package-install-check.md).
- Opt-in notices for the same check (`hooks.packageInstallNotices`, off by default). They never ask and never block: a version published less than 72 hours ago (online mode, plain installs only), and an `npm install` or `npm i` in a project (not `npm ci`, not a global install), which does not require the lockfile and may update it, with a suggestion to add `--ignore-scripts` unless the command has it. See [Notices](docs/package-install-check.md#notices-opt-in).
