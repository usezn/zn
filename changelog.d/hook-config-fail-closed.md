### Security
- Agent hooks: a `hooks.blockDestructiveCommands` list with a rule name zn does not know (a typo, or the name as a block message shows it) no longer turns the destructive-command check off. Names written as `destructive:rm_root_home` or `pipe-to-shell` are accepted; any other unknown name keeps the default rules on. An unknown value for `egressCheck`, `agentInstructionWrites` or `strict` keeps its default as before, and every such value is now reported as a warning by `zn-gate check` and on the hooks' error output.
- Claude Code: the `ConfigChange` hook blocks a change to a skill file over 1 MiB (or one zn cannot read) as not checked, so padding a skill file no longer switches off its hidden-text check. `InstructionsLoaded` records a file over 1 MiB as loaded but not checked.
- Agent hooks: a file tool call (Read, Write, Edit, MultiEdit, NotebookEdit, LSP) that names no file as a single path, a web fetch with no address, and a search whose folder is not a single path are blocked, like a shell call with no command. A search with no folder still searches the working folder.
