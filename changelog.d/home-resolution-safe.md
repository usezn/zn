### Fixed
- zn-gate no longer writes its state into the current folder or the disk root when it cannot find a home folder. `ZN_HOME` is used when it is set; otherwise `HOME` must be absolute, not empty and not `/`. With neither, nothing is written and the command stops with a message that names `HOME` and `ZN_HOME` (the agent hooks block the action with the same message; a Stop event only warns). This covers an empty or relative `HOME`, `HOME=/`, and a user with no passwd entry and no `HOME`, where every npm command used to crash with a system error and the Python package created a folder named `~`. The home folder is looked up when it is needed, not when the package loads, so `--version`, `status` and a hook with `ZN_HOME` set work in a container with no home folder.
