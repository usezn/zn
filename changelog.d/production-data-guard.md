### Added
- Production data guard: the agent hooks now ask before a shell command that drops a database (`DROP DATABASE`, `DROP TABLE` or `TRUNCATE` through `psql`, `mysql`, `sqlite3`, `mongosh` and other SQL clients, including SQL given through a here-document), runs `terraform destroy` or `apply -destroy`, deletes a Kubernetes namespace or uses `kubectl delete --all`, runs `aws s3 rm --recursive`, `aws s3 rb`, `aws s3api delete-bucket` or `aws rds delete-*`, deletes a project, Cloud SQL instance, bucket or cluster with `gcloud`, or force-pushes to `main`, `master`, `release/*` or the default branch. Agents that can ask (Claude Code and others) show the question; agents that cannot (Codex CLI and others) block the command with the reason and the next step. It is on by default; set `hooks.productionDataGuard` to `"deny"` or `"off"` in `~/.zn/config.json` to change it. It reads command text only: scripts, SQL files and REST calls made with a token that was found are not covered. The Python package has the same rules as `zn_gate.prod_guard.check_production_data`. See `docs/production-data-guard.md`.
