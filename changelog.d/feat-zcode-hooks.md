### Added
- `zn hooks install zcode` adds hooks for ZCode desktop app to `~/.zcode/cli/config.json`, turns on `hooks.enabled` (ZCode runs no hook without it; if it was off and you had hooks of your own, the install lists them, and uninstall puts the switch back) and registers the zn "secrets" MCP server there. It blocks the agent from reading or writing secret files, from running shell commands that handle secrets, from sending a secret in an MCP call or in a prompt, and from editing ZCode's own config file. It cannot hide secrets in what a tool returns: ZCode does not let a hook change tool output, so when an output holds a secret zn only adds a notice for the model. ZCode ignores the hooks of a project, so there is no `--project` install, and a hook that cannot start does not block the call by itself (only exit code 2 does); zn's launcher blocks instead when its Node.js is gone. `zn-gate check` reports the ZCode hook and warns when `hooks.enabled` is false or one of zn's entries is switched off.
