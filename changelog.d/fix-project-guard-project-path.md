### Security
- The hook of a project install (`zn hooks install <agent> --project`, the `sh -c` guard written in the shared project files) no longer starts a `zn` or `node` found in an absolute `PATH` entry whose real path is in the project (the folder the hook runs in, the git work tree around it, the project folder the agent names with `CLAUDE_PROJECT_DIR` or `CURSOR_PROJECT_DIR`) or in a `node_modules` folder, nor one that links into the project. A `zn` from a global npm install, which links into its own `lib/node_modules`, still runs; the home folder and the folders above it are never taken as the project. The hook then blocks and says how to install zn-gate, as when `zn` is missing. This is the rule the zn-gate plugins already follow. Antigravity's project guard and the PowerShell project guard on Windows are not changed yet. Run `zn hooks install <agent> --project` again to write the new guard; `zn-gate check` reports the older one.
