### Security
- On Windows, the vault now sets explicit owner-only permissions on its folders (`~/.zn` or `ZN_HOME`, `vault`, `run`), on the session key and on the daemon pipe, reads them back, and does not start if it cannot set or verify them. Before, it trusted inherited permissions, so a `ZN_HOME` outside your profile (such as `C:\zn`) could let another local account read the session key and talk to the daemon.
- `zn run` no longer gives secret values to an unsafe script: a `#!` script (on Windows, a `.cmd` or `.bat` file) that group or others can write, that sits in a folder they can write, or that belongs to another account. Its interpreter opens the script again after zn's last check, so such a script could be swapped in that window. `zn run` refuses and says how to run it through its interpreter instead. A script that only you can write (as installed by nvm, Homebrew, pnpm, pipx or a virtual environment) still works and prints a one-line warning, because another program running as you could still swap it. Native programs and scripts only an administrator can change are not affected.
- The threat model now documents the memory, swap and crash-dump boundary of the unlocked vault.
