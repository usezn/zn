### Security
- Python, LangChain: `guard_langchain_tool` now checks and masks the message of an exception raised by the tool, as it does the tool output, because LangChain (`handle_tool_error`) and LangGraph (`ToolNode(handle_tool_errors=True)`) send that message to the model. A blocked message is handled like a blocked output; a message with a secret is raised again as the same exception type carrying only the masked message. Before, a secret or injected text in a tool error reached the model.
- Python, LangChain: `ZnGuardCallbackHandler` now has `on_tool_error`: when a tool's error message is blocked, or contains a secret while `mask_secrets=True`, the error is replaced by `GuardBlockError`, because a callback cannot rewrite it. Before, the handler did not look at tool errors.
- Python, LangChain: `guard_langchain_tool` now keeps the wrapped tool's `handle_tool_error`, `handle_validation_error` and `response_format="content_and_artifact"` (the content is checked and masked; the artifact is passed through unchanged and is not scanned), and works with arguments LangChain injects: they are forwarded untouched. `InjectedToolCallId` and LangGraph's `InjectedState` and `InjectedStore` are not checked, because the model cannot set them; a generic `InjectedToolArg` is checked like any other argument, because LangChain accepts a value the model sends for it. Before, the wrapper dropped the artifact and needed `handle_tool_error` to be set on the wrapper.
- Python, LangChain docs: the README and the `langchain-agent` example now say to create `ZnGuardCallbackHandler` with `mask_secrets=False` when the tools are wrapped with `guard_langchain_tool`, so the wrapper hides a secret instead of the handler stopping the run first.
