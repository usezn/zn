### Security
- The destructive-command check, the download-and-run check and the egress check read a `timeout` duration written in any form GNU `timeout` accepts (`5`, `1.5m`, `inf`, `infinity`, `1e3`, `+5`, `0x10`) as the duration, also after `-s` and `-k`, so the command behind it is checked.
- Wrapper options that take a value as the next word are now read with it: `nice --adjustment`, `ionice --class`, `--classdata` and `--pid`, `stdbuf --input`, `--output` and `--error`, `time --format` and `--output`, `flock --wait`, `--timeout` and `--conflict-exit-code`, `chroot --userspec` and `--groups`, `nsenter --target`, `--setuid` and `--setgid`, `runuser -w`, `chrt --sched-runtime` and the long forms of the `sudo` options, as separate words or as `--option=value`. When a wrapper has an option zn-gate does not know (an abbreviation such as `nice --adj 5`, or a newer option), the words after it are also checked as the command, so the option cannot hide it.
- Hook settings that turn a check off, relax it or turn on a network lookup (`whenUnavailable: "allow"`, `failMode: "open"`, `blockDestructiveCommands: false` or a shorter list, `agentInstructionWrites: "off"`, `egressCheck: "off"`, `egressAllowHosts`, `checkToolOutputInstructions: false`, `packageInstallCheck: "online"`, `packageInstallAllow`) are read only from the `.zn` folder in the home folder of your operating-system account. A `config.json` in a folder that `ZN_HOME` or `HOME` points to can only add protection there, because a project can set those variables for the agent. If you keep zn's files elsewhere with `ZN_HOME`, move those settings to `~/.zn/config.json` in your account's home folder.
- A change to a project's `.claude/settings.json` during a Claude Code session is not applied when zn-gate cannot check it (the check fails with an error), instead of being allowed unchecked.
- The opt-in cloud check of tool output (`cloudCheckToolOutput`) now also replaces national ID numbers (Spanish DNI and NIE, US SSN) with `[ID]` before sending. IP addresses, names, postal addresses and usernames are still not removed; the docs now say so.
