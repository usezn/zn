### Security
- The sensitive-file rule now matches Windows paths and mixed separators, such as `C:\Users\name\.ssh\id_rsa` and `C:/Users/name\.aws/credentials`, in the same places it matches POSIX paths, and the common variable forms (`%USERPROFILE%`, `$env:USERPROFILE`, `$HOME`) and a quoted user name with a space.
- The hidden-element rule now looks at real attributes: the `hidden` attribute, `aria-hidden="true"`, a style that hides the element or gives it no size, or a hiding class (`hidden`, `visually-hidden`, `sr-only`, `d-none`, `invisible`, `is-hidden`). A style hides an element when it sets `display:none`, `visibility:hidden`, zero opacity or font size, a width and height of at most 1px, a zero or 1px height with `overflow:hidden`, or a clip that leaves nothing visible; `overflow:hidden` alone does not. A name that only contains the word (`data-hidden`), a style value such as `opacity:0.5` and plain mentions of a tag no longer count.
- The Base64 check treats `openssl` as a decoder only in its decode forms (`openssl base64 -d`, `openssl enc -d -base64`), so encoding and hashing commands that follow an `echo` are no longer decoded and blocked; a stdin flag such as `-in -` does not hide the decode.
- In the Node package, a compatibility character with no folded form (such as U+2072) is now kept in the text that rules match against instead of becoming the word "undefined". The Python package already did this.
- The hidden-element and path rules read spaces as ASCII spaces only, so the Node and Python packages give the same answer on characters such as U+0085, U+001C and U+FEFF.
