### Security
- Secret redaction (npm and Python packages): a provider key followed by a suffix that starts with `_` or `-` (for example `sk_live_..._old` or a key ending in `-backup`) was left in the text, because the match had to end at the key. The key is now redacted together with the suffix. A fixed-length key with letters or digits right after it is still a different, longer token.
- Node.js library: `redactSecrets` and `sanitizeToolResult` could leave a provider key, such as a Stripe key, unredacted when a wider match of another kind covered it (for example `key: sk_live_...` followed by `NAME=` on the same line). The provider formats are now matched on their own, as in the Python package.
- A CI test now redacts seeded random texts of fake keys with both packages and fails if either package leaves a key in the output.
