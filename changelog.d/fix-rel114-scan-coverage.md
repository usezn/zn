### Changed
- `zn-gate scan` (npm and PyPI) no longer exits `0` when its result does not cover every file it should have read. It exits `3` when no file was read, or when a file or folder was skipped (2 MiB or larger, cannot be read, not a regular file, a binary `.key` file). Findings still exit `1`. The skipped files are still listed, and `--format json` has a new `incomplete` field. Pass `--allow-partial` to keep exit `0` when only some files were skipped (an empty scan still exits `3`). CI jobs that run `zn-gate scan` may now see this new non-zero exit, for example when the repository has a JSON or Markdown file of 2 MiB or more.
