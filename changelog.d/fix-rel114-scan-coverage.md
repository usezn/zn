### Added
- The GitHub Action has an `allow-partial` input (default `false`, needs zn-gate 1.14.0 or later) that passes `--allow-partial` to the scan. A scan that exits `3` now fails the step with its own message instead of a generic error, and `format: sarif` still writes the report.

### Changed
- `zn-gate scan` (npm and PyPI) no longer exits `0` when its result does not cover every file it should have read. It exits `3` when no file was read, or when a file or folder was skipped (2 MiB or larger, cannot be read, not a regular file, a binary `.key` file). Findings still exit `1`. The skipped files are still listed, and `--format json` has a new `incomplete` field. Pass `--allow-partial` to keep exit `0` when only some files were skipped (an empty scan still exits `3`). CI jobs that run `zn-gate scan` may now see this new non-zero exit, for example when the repository has a JSON or Markdown file of 2 MiB or more. The Python scan no longer lists links found inside the folder as skipped files (the Node scan never did), and the Node scan now lists a named pipe or socket as not read and reads a single file you name whatever its extension, as the Python scan does.
