### Security
- Writes to an agent instruction file (`CLAUDE.md`, `AGENTS.md`, `GEMINI.md`, `.cursorrules`, `.github/copilot-instructions.md`, `.cursor/rules/*`, memory files) made inside a `python -c` or `node -e` one-liner now get the same question as any other write to those files. zn reads a quoted file name given to `open(..., "w"/"a"/"x")`, `Path(...).write_text`, `write_bytes`, `fs.writeFile`, `writeFileSync`, `appendFile`, `appendFileSync` or `createWriteStream`, with `./`, `../` and `~/` prefixes; reading the file stays allowed. `POLICY_RULES_VERSION` is bumped.
- Interpreter code too long for zn to read in full (over 20,000 characters), or a quoted target spelled with escapes such as a hex or unicode escape, is no longer let through: it gets the same question (and the same refusal in strict mode) as a write to an instruction file. Quoted Windows paths with backslashes (raw or doubled, for example a raw path to AGENTS.md) are now read as paths and checked.
