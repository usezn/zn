### Security
- A first-use approval of a secret now belongs to the value it was given for. Before, `zn secret rm` kept the approvals, so a new value stored under the same name inherited them and a command you had approved for the old value could read the new one without asking. Now removing a secret deletes its approvals, and every time a value is set or replaced the secret gets a new random id that approvals are tied to, so replacing a value without removing it asks again too. Storing the same value again changes nothing. Approvals saved by earlier versions carry no id and no longer count: the first time a command uses a secret after you update, zn asks once more, and that approval is kept from then on.
