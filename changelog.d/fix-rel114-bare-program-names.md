### Security
- Programs zn-gate starts by name now come from the absolute PATH entries only, never from the current folder or a relative PATH entry: `git` (checked when a file write holds secret placeholders), the MCP server command under `zn-gate shield` (which now also starts the server with that PATH and, on Windows, without the current-folder search, so `cmd /c npx ...` or `sh -c ...` cannot pick a program from the project), the `claude` CLI during `zn hooks install`, and `sh` in `zn-gate check` and the Antigravity self-check. zn-gate also runs `git` with `core.fsmonitor` turned off, so a program named in the repository's `.git/config` does not run, and treats a repository git refuses to read as possibly committed. In 1.13.1, a `git.exe` or a server program of the same name placed in the project could run instead on Windows, or anywhere through a relative PATH entry.

### Fixed
- Windows: `zn-gate check` reported Claude Code as NOT protected ("its hook cannot start (ENOENT)") when Git Bash's `sh` was not on the PATH, which is the default for Git for Windows, although the hook worked. check now finds Git Bash the way Claude Code is set up: `CLAUDE_CODE_GIT_BASH_PATH`, else the `bin\bash.exe` next to `git`.
