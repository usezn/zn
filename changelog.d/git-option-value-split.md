### Fixed
- A git global option, or its value, that the shell may turn into several words is now blocked, so it cannot add options such as `-c core.pager=...`. This covers the values of `-C`, `--git-dir`, `--work-tree`, `--namespace`, `--exec-path`, `--super-prefix`, `--config-env`, `--attr-source` and `-c` (as a separate word or after `=`) and every word before the subcommand, when it holds: a variable or `$(cmd)` outside quotes that zn cannot resolve or that resolves to more than one word (`git -C $DIR status`, `git $OPTS status`); any variable outside quotes once the command sets `IFS`; `$PWD` or `$OLDPWD` after the command changes directory; a pattern or a brace list outside quotes (`git -C {a,b} status`, `git -C a* status`); `"$@"` or `"${list[@]}"`; PowerShell splatting (`@args`, `@(...)`); or a cmd.exe `%NAME%`. A variable the same command writes (`read`, `for`, `select`, `printf -v`, `mapfile`, `declare`, `export`, `eval`) is no longer read from the environment, and `IFS` or `cd` written with quotes, a backslash or an ANSI-C string count the same as the plain spelling. Quote the value and the command is allowed (`git -C "$DIR" status`, `git -C "$(git rev-parse --show-toplevel)" status`); so are values zn resolves to one word and the arguments of a subcommand (`git push origin $BRANCH`).
