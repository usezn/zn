### Security
- The vault daemon no longer answers a request for a stored value that says nothing about what it is for. Restores by the hooks and the secrets broker (`zn run`, `secrets_http_request`, `secrets_render_file`) now name a destination or a purpose, and the daemon checks it against what it holds: the restoration table, the secret's mode, the commands, executables, hosts and places you allowed, and the organization policy. A request with no context, or one the daemon does not know, is refused and recorded in the audit log.
- Plain values are read only by the output masker, through a call the daemon records (one entry a minute for each agent and tool) and refuses to anything else. `zn secret adopt`, `zn secret import` and `zn env shadow` no longer read a value back, and `zn env unshadow` waits for your confirmation on the vault's own prompt before the plain text leaves the vault.
- An agent or tool name in a request is recorded and grants nothing, and on Linux and macOS the daemon refuses to start unless its socket, session key and folder belong to your user and are closed to others.
- A vault started by an older zn-gate counts as outdated: `zn unlock` restarts it.
