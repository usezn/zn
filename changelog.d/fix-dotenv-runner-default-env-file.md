### Security
- The shell hook refuses `dotenvx run`, `dotenvx get` and the other `dotenvx` steps that load the default file, and `dotenv` (dotenv-cli) run without `-e`, when the project `.env` holds a plain-text secret or an encrypted value, the same as when the command names `.env` with `-f`. Before, only the form that typed the file name was checked, so `dotenvx run -- printenv` printed the values. With `--convention` (dotenvx) or `-c` (dotenv-cli) these files are checked too: `.env.local`, `.env.development`, `.env.production`, `.env.test`, `.env.development.local`, `.env.production.local` and `.env.test.local`. The check follows a `cd` or `pushd` earlier in the command, ignores file options that belong to the wrapped command instead of the runner, and treats a `dotenvx` step it cannot identify as loading the default file. A project whose `.env` has no secret, or has none, is not affected.
