### Security
- A tool result larger than 4 MB is now blocked by default (rule `size:truncated`). Only its first 4 MB and its last window were scanned, so an injection in the middle of a large result was allowed with `truncated` set. This applies to the SDK functions `sanitizeToolResult`, `checkToolResult` and `scanToolResult`, and `guardTool` with `checkResult` (Node.js), to `check_tool_result`, `sanitize_tool_result`, `@guard(check_result=True)` and the framework integrations (Python), and to the MCP tool `check_tool_result`. The agent hooks (Claude Code, Codex, Cursor and the others) do not use this check and are unchanged: they still replace the parts of an output too large to check for secrets in time with a short notice. A legitimate result can be caught too, for example a base64 screenshot over 4 MB or a large database dump; the block message names the opt-out. To allow such results, set `ZN_ALLOW_TRUNCATED=1`, or pass `allowTruncated: true` (Node.js) or `allow_truncated=True` (`check_tool_result`, `sanitize_tool_result`); an allowed result is marked `truncated`. `blockTruncated`, `block_truncated` and `ZN_BLOCK_TRUNCATED=1` still force the block. The MCP shield already blocked results over 32 MB and is unchanged.
