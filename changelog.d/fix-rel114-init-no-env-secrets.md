### Security
- `zn init` no longer writes keys or tokens read from the environment (`ZN_API_KEY`, `ZN_JWT_SECRET`, `ZN_MCP_WS_TOKEN`, `ZN_DB_KEY`) into `zn.json`, so a config file that is committed or shared does not carry them; they stay in the environment. On Linux and macOS the file is now created readable by its owner only (mode 0600).
- The configuration saved locally after a remote sync no longer carries keys or tokens, and neither it nor `zn init` writes the namespace or KMS key id and region when they come from the environment. Both files are written atomically and owner-only (mode 0600) on Linux and macOS, and a `zn.json` that is a symbolic link is refused.
