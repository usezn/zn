### Security
- The pre-tool check now also sees a curl configuration file (or a folder curl reads its default configuration from) named by a command through a folder inside an option (`--target-directory=DIR`, `--directory=DIR`, `cp -tDIR`, `tar -CDIR`, `unzip -dDIR`, `7z x -oDIR`) or through `$PWD`, and refuses the command, as it already did for a separate argument. A folder written with `$OLDPWD` is refused, since zn cannot follow it. A place built from a variable zn does not resolve (`$DIR`, `${DIR%/}`, `${1:-.}`, `${HOME:-~}`, `${a:-${b}}`) may be empty or any folder, so it is judged by what the command does with it, not by the text around it: when a curl in the same command reads a configuration (`-K file`, or `~/.curlrc` when `-q` is not its first option), the command is refused if it writes to such a place in a way that can put a configuration there: a redirect (`>`, `>>`) of a command other than that curl, `tee`, `dd of=`, `sed -i`, an archive extracted into it (`tar -x -C`, `unzip -d`, `7z -o`), or a `cp`, `mv`, `install`, `ln` or `rsync` destination when the copy is recursive, moves a folder, or copies a file whose name is a configuration's name (`.curlrc`, `curlrc`, `_curlrc`, the name given to `-K`) or is itself built from a variable or a pattern. The message suggests `curl -q` or a fixed path. A plain literal default (`${DIR:-.}`) is read as that literal, and copies of ordinary files, sources named by a variable and extractions next to a curl that reads no configuration stay allowed. A file sent with `@file` (`-d @file`, `-F name=@file`, `--data-urlencode name@file`) whose name is built from a variable zn does not know is now refused, as an upload name built that way already was.
