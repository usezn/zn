### Fixed
- The hook runner treats the tool output that GitHub Copilot delivers in `toolResult.textResultForLlm` (or `tool_result.text_result_for_llm`) as model content, like `tool_response` and `tool_output`: it is scanned by the content scanner and never turned into a file path, so malformed text there no longer trips the fail-closed refusal that is meant for path fields. The other parts of that field, and a `toolResult` or `tool_result` field from any other agent, are still checked. Every other field is still checked, the top-level `metadata` field included; the one further exemption is a `metadata` object the adapter itself copied into the scrubbed tool output.
