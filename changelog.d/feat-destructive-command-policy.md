### Added
- The agent hooks now refuse two kinds of destructive shell command by default: a recursive delete of the home folder, the filesystem root or a system folder, and a write to a disk device. A blocked command is not run, and the agent is told to ask you to confirm first. Four more rules (a download piped to a shell such as `curl ... | sh`, `chmod -R` or `chown -R` on the root or a system folder, a fork bomb, and a download written into a shell startup file) are off by default. To change this, set `{"hooks": {"blockDestructiveCommands": ...}}` in `~/.zn/config.json` (`true` = all six rules, `false` = off, or a list of rule names), or set `ZN_BLOCK_DESTRUCTIVE=0` (off) or `ZN_BLOCK_DESTRUCTIVE=1` (all six) in the environment. It reads command text only and is not a sandbox. SDK users get `checkCommand` (Node.js, `zn-gate/lib/client`) and `check_command` (Python), which always apply all six rules. See `docs/destructive-commands.md`. `POLICY_RULES_VERSION` is `2026-10-19.43`.
