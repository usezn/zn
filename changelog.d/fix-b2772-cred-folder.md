### Security
- A program that reads every file of a folder it is given can no longer be pointed at a credential folder such as `~/.aws`, `~/.ssh`, `~/.kube`, `~/.config/gh`, `~/.docker` or `~/.gnupg`: `tar c`, `zip -r`, `7z a`, `rsync`, `cp -r`, `scp -r`, `grep -r`, `rg`, `ag` and `find ... -exec` are refused, also after `tar -C DIR` or a `cd DIR` followed by `.`, and also when the folder is named with a pattern or braces (`~/.a*s`, `~/.[a]ws`, `~/.{aws,x}`). The same programs are refused on a parent folder that contains one (`~`, `~/.config`) when they read it recursively. `find` on a credential folder may only run `chmod`, `chown`, `chgrp`, `touch`, `ls`, `stat` or `rm` through `-exec`. File names listed from a credential folder and handed to another program through a pipe (`find ~/.aws | xargs cat`, `echo ~/.aws | xargs tar c`) are refused, and so is a name list read from standard input by `tar -T -`, `zip -@`, `cpio -o` or `rsync --files-from=-` unless it comes from `find`, `ls` or `git ls-files` on another folder. Listing a folder (`ls`, `du`) and the usual project commands (`tar czf out.tgz src`, `zip -r app.zip dist`, `grep -r TODO .`) stay allowed.
- Once a command lists a credential folder (`find ~/.aws`, `ls ~/.ssh`, `echo ~/.aws`), only programs that merely filter or count the names may follow in the pipeline (`sort`, `uniq`, `head`, `tail`, `grep`, `cut`, `tr`, `wc`, `tee`, `cat`, and `awk`/`sed` scripts that cannot run a command); `parallel`, `sh`, `while read`, `pax`, `afio`, `awk 'system(...)'`, `sed s///e` and any other consumer are refused. `tar` name lists are also recognised from `/dev/fd/0` and in old-style option bundles (`tar czfT out.tgz -`). `pax -w` and `diff -r` on a credential folder are refused as recursive readers.
