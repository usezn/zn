### Fixed
- The command policy now also refuses a `.env` read whose name is spelled by cmd.exe or the shell instead of by the text. cmd.exe: caret escapes (`type .e^nv`, read on Windows and wherever cmd or a batch file is the command; a caret inside double quotes stays literal), and variable units inside a name (`type .e%OS:~0,0%nv`, `%NAME%`, `!VAR:old=new!`). Shell: every expansion unit is read as removed, and as its default word, whatever the environment holds (`cat .en${UNSET}v`, `cat .e${HOME:0:0}nv`, `cat .e${UNSET:-n}v`, `cat .e$UNSET""nv`, `cat .en$(echo)v`, `$@`, `$1`). Ordinary uses of `^` in a POSIX shell, a folder named `cmd`, and trailing dots on POSIX systems are still allowed.
