### Fixed
- The command policy now also refuses a `.env` read whose name is spelled by cmd.exe or the shell instead of by the text. cmd.exe: caret escapes (`type .e^nv`, read on Windows and wherever cmd or a batch file is the command; a caret inside double quotes stays literal), and variable units inside a name (`type .e%OS:~0,0%nv`, `%NAME%`, `!VAR:old=new!`). Shell: every expansion unit is read as removed, as its default word, and as any text, so a word that comes out empty, or that a variable or command substitution could complete, is refused whatever the hook's environment holds (`cat .e${X}v`, `cat ${D}env`, `cat .e$(echo n)v`) as long as the word keeps at least two literal characters of `.env`, `.env.*` or an SSH key name; a name held wholly by a variable the line does not assign is still not read (`cat .en${UNSET}v`, `cat .e${HOME:0:0}nv`, `cat .e${UNSET:-n}v`, `cat .e$UNSET""nv`, `cat .en$(echo)v`, `$@`, `$1`). Ordinary uses of `^` in a POSIX shell, a folder named `cmd`, and trailing dots on POSIX systems are still allowed.
