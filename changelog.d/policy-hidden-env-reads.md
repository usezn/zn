### Fixed
- The command policy now also refuses a `.env` read whose name is spelled by cmd.exe or the shell instead of by the text. cmd.exe: caret escapes (`type .e^nv`, read on Windows and wherever cmd or a batch file is the command; a caret inside double quotes stays literal), and variable units inside a name (`type .e%OS:~0,0%nv`, `%NAME%`, `!VAR:old=new!`). Shell: every expansion unit is read as removed, and as its default word, whatever the environment holds (`cat .en${UNSET}v`, `cat .e${HOME:0:0}nv`, `cat .e${UNSET:-n}v`, `cat .e$UNSET""nv`, `cat .en$(echo)v`, `$@`, `$1`). A quoted closing bracket does not end an expansion early (`cat .en$(: ")")v`, `cat .e${U:+"}"}nv`). cmd variable names are anything up to the next `%` or `!` (`%ProgramFiles(x86):~0,0%`), and with delayed expansion (`cmd /v:on`) an `!` without a partner is read as removed (`type .e!nv`). Ordinary uses of `^` in a POSIX shell, a folder named `cmd`, and trailing dots on POSIX systems are still allowed.
