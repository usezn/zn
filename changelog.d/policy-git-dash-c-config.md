### Security
- The shell policy now reads `git -c KEY=VALUE`, `git -c KEY` and `git --config-env=KEY=ENVVAR` the same way as the GIT_CONFIG_* variables: a key that makes git run a program (core.pager, core.editor, core.sshCommand, diff.external, filter.*.clean, credential.helper, gpg.program, sequence.editor, an alias starting with !, and similar) is read as shell code, a key that loads configuration or hooks (core.fsmonitor, core.hooksPath, include.path, protocol.ext.allow) is refused unless it is a plain switch, and a key or value that cannot be read as a literal is refused. Quiet uses such as git -c user.name=x commit, git -c core.pager=cat log or git -c color.ui=always log are still allowed.
