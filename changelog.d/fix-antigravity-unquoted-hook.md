### Fixed
- Antigravity: `zn hooks install antigravity` wrote the launcher path in quotes, but Antigravity runs hook commands without a shell, so the quotes became part of the file name and the hook never started. The path is now written without quotes, and `zn-gate check` runs the hook the same way and asks for a reinstall when it finds the old quoted form.
- Antigravity: the question zn asks before a recursive shell search over a folder with a plain-text `.env` now reads every command of the line, not only the first. It follows `cd`, sees through `sudo`, `env`, `command`, `nice`, `timeout` and `xargs`, covers `git grep`, and no longer loses the folder when the pattern is quoted with `|` or `;`.
- Antigravity: that question also reads `bash -c` and `sh -c` strings (one level), asks when a recursive search names its folder through a variable or a substitution, and asks, instead of searching on, when a command changes folders more than about 30 times before a search, so a long chain of `cd` can no longer slow the hook down.
- Antigravity: the shell-search question no longer allows a very long line (more than 500 command segments) without reading it, nor a search after a `cd` whose folder is a variable or a substitution. A leading `~` in a `cd` target or a search path now means your home folder. The MCP row of the compatibility table now says that secrets and `__ZN_` markers in MCP arguments are blocked and personal data asks.
