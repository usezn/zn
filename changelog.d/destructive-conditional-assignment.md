### Security
- The destructive-command rules now read a variable that a conditional assignment may have changed as holding every value it may have, and the worst one decides. Before, `D=/home/alice; [ -n "$X" ] && D=./build; rm -rf "$D"` was read as `rm -rf ./build` and allowed, although at run time `D` may still be the home folder. The same applies to an assignment after `&&` or `||`, inside an `if`, `case`, `while`, `until` or `for` block, inside a `( )` or `{ }` group and in a function body (also for the download-and-run and startup-file rules and for the network allowlist). An assignment that always runs still replaces the old value, so `D=/home/alice; D=./build; rm -rf "$D"` stays allowed. A variable with more than 16 possible values, or a command whose variables give more than 64 combinations, is refused rather than guessed at.
