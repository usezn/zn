### Fixed
- Python `guard(partial(tool, session))`, and `@guard` with a client object that holds a container that cannot be iterated (such as the connection pool of a `requests.Session`), no longer fail with `NotImplementedError`: what cannot be read inside an application object is left out, and a container that cannot be read anywhere else blocks with rule `type:unscannable`.

### Security
- Python `@guard` now reads plain application objects in the arguments of a guarded function down to 32 levels, as it does for a result, and checks the text it finds there. Before, text more than ten levels deep inside such an object was skipped. What is deeper than 32 levels blocks (rule `size:nesting`). Data (dicts, lists, namespaces, data models) nested deeper than ten levels still blocks as before, and clients, sessions and dependency containers (a database engine, an HTTP session) keep working. Inside such an object, a dictionary or list is also read down to 32 levels. Known limits: an object with more than 100,000 values in its attributes is left out of the check rather than blocked, and the connection settings of a database engine (such as SQLAlchemy `connect_args`) are not read.
- Python `@guard(mask_secrets=True)` and the framework integrations no longer fail with `RecursionError` on a result that contains itself, such as a dictionary that holds a reference to itself. Such a result, one nested deeper than ten levels or one with more than 100,000 values is blocked with rule `size:nesting` or `size:items`. `sanitize_tool_result(data)` raises `SanitizeLimitError`, a `ValueError`, for the same data.
- Python `@guard(mask_secrets=True)` now masks a secret that a streamed result splits across chunks, for generators and async generators with text or bytes chunks. The last 16 KiB of text are held back, as it arrived, until more text or the end of the stream arrives, and a secret that reaches into them keeps the text from its start held too, whatever the size of the chunks: text is passed on only up to a point where masking it in two parts gives the same as masking it whole, looking further and further back so a long secret such as a private key is kept whole (tested with chunks of 4 KiB to 300 KiB, as text and as bytes, on compact JSON, URL lists and private keys). When the held text passes 256 KiB with a secret across every place it could be cut, such as a single value longer than that, the stream is blocked (rule `secret:unmaskable`) instead of passing part of the secret on. Each chunk the function yields still gives one chunk out, but it is empty while its text is held, so the text comes out later and in larger pieces (a short stream comes out whole at its end), in order and in full, also when the function fails. Each chunk is still checked as before, and the held text is withheld when a chunk blocks.
