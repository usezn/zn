### Added
- New, off by default: if you run `zn-gate connect` and also add `{"hooks": {"cloudCheckToolOutput": true}}` to your own `~/.zn/config.json` (both are read from the home folder of your operating-system account, not from the `HOME`, `USERPROFILE` or `ZN_HOME` variables, so environment variables and a project's settings cannot enable it; the hook uses only the key `zn-gate connect` saved, and the path stays off while `ZN_HOME` or `HOME` points zn-gate at another folder), the Claude Code hook also sends a sample of the results of web fetches, MCP tools and shell commands to the zn cloud to look for hidden instructions aimed at the agent. Until now tool output never left your machine, and it still does not unless you turn this on, including if you already ran `zn-gate connect`. The sample is at most 16 KiB, counted in bytes of UTF-8 text (the first 12 KiB and the last 4 KiB), is sent only after secrets and personal data (email addresses, phone numbers, IBANs and card numbers) are removed, skips a result the local check already flagged, and goes only to `api.usezn.com`. The cloud answer can only add the note the local check adds; if the call fails nothing is blocked or changed, and an answer with a verdict that is neither allow nor block adds that note without blocking. Without `zn-gate connect`, or without that setting, nothing is sent. Other agents send nothing. Remove the setting, or set it to `false`, to turn off just this path and keep the prompt check.

### Changed
- The data-flow notes in the READMEs and docs now say that tool output is sent in this one opt-in case.
