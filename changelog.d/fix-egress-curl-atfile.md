### Security
- The pre-tool check now reads `@file` in the value of curl's `-d`, `--data`, `--data-binary`, `--data-raw`, `--data-ascii`, `--data-urlencode`, `--json`, `--variable`, `-F` and `--form` (also `name=@file`, `name=<file`, `name@file` and the form without a space, as in `-d@.env`) as a file that is sent, also when curl runs behind `sudo`, `env`, `timeout`, `stdbuf` or `nice`. A `.env` file with values, a credential file, a private key or a file in zn's own folder named that way is refused, the same as when it is given to `-T`, `--upload-file` or `wget --post-file`. Before this, an agent could send such a file to another computer with `curl --data-binary @file`. Plain data such as `-d 'a@b.com'`, `-F 'email=me@example.com'` or `-d @payload.json` stays allowed.
