### Security
- The pre-tool check reads the files that a command asks a program to send, in any command: `@file` and `@a,b` values (curl `-d`, `--data`, `--data-binary`, `--data-raw`, `--data-ascii`, `--data-urlencode`, `--json`, `-F`, `-H`; `gh api -F`), `name=@file`, `name:=@file` and `name=<file` (curl, HTTPie, xh), `name@file` with any name (curl `--data-urlencode`, `--url-query`, `--variable`, HTTPie), the files that a `{...}` pattern stands for in curl's `-T` and `--upload-file`, and each piece of a word with spaces or with printf or echo escapes such as `\n`, `\012`, `\x0a` or `\u000a`. This also holds in the `--option=value` form and when an option is glued to its value (`-d@.env`, `-4d@.env`, `-T.env`, `-sT.e{nv}`). A `.env` file with values, a credential file, a private key or a file in zn's own folder is refused, the same as when it is given to `cat`.
- A curl command is refused when it reads its options from standard input, a pipe or a value built at run time (`-K -`, `--config /dev/stdin`, `-K <(...)`), or when it uploads a file whose name is built at run time, because zn cannot see which files it would send. A variable set earlier in the same command is read like the rest of the command.
- Curl configuration files (`-K file`, `--config file`, and the `~/.curlrc` that curl reads by default) are read like the command itself, with curl's own rules: one option per line, `=` or `:` separators, quoted values with their backslash escapes, short options such as `-T.env`, and a `config` line followed into the file it names. A configuration that sets curl variables is refused. So are a configuration path that leads to standard input however it is written (`//dev/stdin`, `/dev/./stdin`, `../../dev/stdin`, `/proc/thread-self/fd/0`, a link or a fifo), a configuration file that does not exist yet and is written by the same command, a `curlrc` written by the command, and a command that changes `CURL_HOME`, `XDG_CONFIG_HOME` or `HOME` (with `=` or `+=`) before a curl that runs without `-q`.
- A relative configuration path is looked up in every folder that a `cd` in the command may lead to. A configuration that another word of the command names (through `cp`, `mv`, `ln -sf`, `sed -i`, `dd of=`, a here-document, or a separate argument without variables that names the folder that holds it or a pattern that matches it) is refused, and so is a command that names the folders curl reads its default configuration from in the same way.
- curl's `--expand-*` options are read with the values of their `--variable` settings, and a `--variable name@file` value is read from that file. Functions in `--expand-*` values (`{{f:64dec}}`, `{{f:trim}}`) are refused where a file is read. `~+` and `~0` mean the working folder, and `~-` and deeper directory-stack entries (`~1`) are refused like `$OLDPWD`, because zn cannot tell which folder they name. `$PWD` is the folder the command runs in.
- A folder given inside an option (`--target-directory=DIR`, `--directory=DIR`, `cp -tDIR`, `tar -CDIR`, `unzip -dDIR`, `7z x -oDIR`), as a separate argument, or through `$PWD` is checked for a curl configuration file, and the command is refused if it names one or names the folder curl reads its default configuration from. A folder written with `$OLDPWD` is refused.
- A place built from a variable that zn does not resolve (`$DIR`, `${DIR%/}`, `${1:-.}`, `${HOME:-~}`, `${a:-${b}}`) may be empty or any folder, so the command is judged by what it does with that place. When a curl in the same command reads a configuration (`-K file`, or `~/.curlrc` when `-q` is not its first option), the command is refused if it writes to such a place in a way that can put a configuration there: a redirect (`>`, `>>`) of a command other than that curl, `tee`, `dd of=`, `sed -i`, an archive extracted into it (`tar -x -C`, `unzip -d`, `7z -o`), or a `cp`, `mv`, `install`, `ln` or `rsync` destination when the copy is recursive, moves a folder, or copies a file named like a configuration (`.curlrc`, `curlrc`, `_curlrc`, or the name given to `-K`) or a name built from a variable or a pattern. The refusal suggests `curl -q` or a fixed path. A plain literal default such as `${DIR:-.}` is read as that literal. Copies of ordinary files, sources named by a variable, and extractions next to a curl that reads no configuration stay allowed.
- A command that downloads into such a place (`curl -o $F`, `curl --output=$F`, `wget -O $F`) is refused when a curl in the same command reads a configuration, since the download may be that configuration. A curl whose output goes there by redirection (`curl URL > $F`) is refused inside a `for`, `while` or `until` loop or when it reads a `-K` file, because a later pass could read what an earlier one wrote.
- A file sent with `@file` (`-d @file`, `-F name=@file`, `--data-urlencode name@file`) whose name is built from a variable that zn does not know is refused.
- A command with many assignments or wrappers before the program is checked as if it ran curl, and an upload pattern that stands for too many names is refused.
- This stops an agent from sending such a file to another computer with `curl --data-binary @file` or similar commands. Plain data such as `-d 'a@b.com'`, an e-mail address, `@scope/pkg` or `-d @payload.json` stays allowed. So do `curl URL | tee $LOG`, since `tee` only takes the output of that curl, and `curl --data-raw @$NAME`, since `--data-raw` never reads a file and sends its value as text (a literal `@.env` after it is still refused). A `tee` fed by anything else, or followed by another curl, is refused.
