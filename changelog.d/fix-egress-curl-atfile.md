### Security
- The pre-tool check now reads the files that a command word asks a program to send, in any command: `@file` and `@a,b` (curl `-d`, `--data*`, `--json`, `-F` with a list of files, `-H`; `gh api -F`), `name=@file`, `name:=@file` and `name=<file` (curl forms, HTTPie, xh), `name@file` with any name (curl `--data-urlencode`, `--url-query`, `--variable`, HTTPie), the names a `{..}` pattern stands for in curl's `-T` (also in a cluster such as `-sT` or `-4T`) and `--upload-file`, and each piece of a word with spaces or with printf/echo escapes such as `\n`, `\012`, `\x0a` or `\u000a`, including its `upload-file` and `-T` lines (a curl configuration given to `curl -K -`), also in the `--option=value` form and glued to a curl option (`-d@.env`, `-4d@.env`, `-T.env`, `-sT.e{nv}`). A `.env` file with values, a credential file, a private key or a file in zn's own folder named that way is refused, the same as when it is given to `cat`. A curl command that reads its options from standard input, a pipe or a value built at run time (`-K -`, `--config /dev/stdin`, `-K <(...)`), or that uploads a file whose name is built at run time, is now refused, because zn cannot see which files it would send; the value of a variable set earlier in the same command is read like the rest of the command. A curl configuration file (`-K file`, `--config file`, and the `~/.curlrc` that curl reads by default) is now read by zn like the command itself, and a path that leads to standard input however it is written (`//dev/stdin`, `/dev/./stdin`, `../../dev/stdin`, `/proc/thread-self/fd/0`, a link or a fifo), a configuration file that does not exist yet (written by the same command), a `curlrc` written by the command and a command that changes `CURL_HOME`, `XDG_CONFIG_HOME` or `HOME` (with `=` or `+=`) before curl without `-q` are refused. curl's `--expand-*` options are read with the values of their `--variable` settings, and `~+` and `~-` are read as the working folder. Configuration files are read with curl's own rules (an option per line, `=` or `:`, quoted values with their backslash escapes, short options such as `-T.env`), a `config` line is followed into the file it names, and a configuration that sets curl variables is refused; a relative configuration path is looked up in every folder a `cd` in the command may lead to, and a configuration that another word of the command names (`cp`, `mv`, `ln -sf`, `sed -i`, `dd of=`, a here-document, or a separate argument without variables that names the folder that holds it or a pattern that matches it) is refused, and so is a command that names in the same way the folders curl reads its default configuration from. curl functions in `--expand-*` values (`{{f:64dec}}`, `{{f:trim}}`) are refused where a file is read, a `--variable name@file` value is read from that file, `~0` and `~+0` are read as the working folder and deeper directory-stack entries (`~1`) are refused in curl and read as every folder the command may be in elsewhere, and `$PWD` is the folder the command runs in. Before this, an agent could send such a file to another computer with `curl --data-binary @file` and similar commands. A command with dozens of assignments or wrappers before the program is now checked as if it ran curl, and an upload pattern that stands for too many names is refused. Plain data such as `-d 'a@b.com'`, an e-mail address, `@scope/pkg` or `-d @payload.json` stays allowed.
