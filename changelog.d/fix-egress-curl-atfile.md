### Security
- The pre-tool check now reads the files that a command word asks a program to send, in any command: `@file` and `@a,b` (curl `-d`, `--data*`, `--json`, `-F` with a list of files, `-H`; `gh api -F`), `name=@file`, `name:=@file` and `name=<file` (curl forms, HTTPie, xh), `name@file` with any name (curl `--data-urlencode`, `--url-query`, `--variable`, HTTPie), the names a `{..}` pattern stands for in curl's `-T` (also in a cluster such as `-sT` or `-4T`) and `--upload-file`, and each piece of a word with spaces or with printf/echo escapes such as `\n`, `\012`, `\x0a` or `\u000a`, including its `upload-file` and `-T` lines (a curl configuration given to `curl -K -`), also in the `--option=value` form and glued to a curl option (`-d@.env`, `-4d@.env`, `-T.env`, `-sT.e{nv}`). A `.env` file with values, a credential file, a private key or a file in zn's own folder named that way is refused, the same as when it is given to `cat`. A curl command that reads its options from standard input, a pipe or a value built at run time (`-K -`, `--config /dev/stdin`, `-K <(...)`), or that uploads a file whose name is built at run time, is now refused, because zn cannot see which files it would send; the value of a variable set earlier in the same command is read like the rest of the command. Before this, an agent could send such a file to another computer with `curl --data-binary @file` and similar commands. A command with dozens of assignments or wrappers before the program is now checked as if it ran curl, and an upload pattern that stands for too many names is refused. Plain data such as `-d 'a@b.com'`, an e-mail address, `@scope/pkg` or `-d @payload.json` stays allowed.
