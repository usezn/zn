### Security
- The shell policy now reads environment variables that make git run a program as code, the way it reads an alias: GIT_PAGER, GIT_EDITOR, GIT_SEQUENCE_EDITOR, GIT_SSH_COMMAND, GIT_SSH, GIT_ASKPASS, GIT_EXTERNAL_DIFF, GIT_PROXY_COMMAND, PAGER, EDITOR and VISUAL, whether set before a command, after env, or exported earlier in the line. GIT_CONFIG_COUNT with GIT_CONFIG_KEY_n and GIT_CONFIG_VALUE_n, and GIT_CONFIG_PARAMETERS, are checked the same way, and keys that load configuration or hooks (core.fsmonitor, core.hooksPath, include.path, init.templateDir) are refused unless they are plain switches. A key or value that is not a literal is refused. The agent-level environment check lists the same variables. Quiet uses such as GIT_PAGER=cat or GIT_EDITOR=true are still allowed. The same check now reads git -c name=value and --config-env pairs, judges every GIT_CONFIG_KEY_n and GIT_CONFIG_VALUE_n assignment of an index (a decoy before the real one no longer hides it, and only the decimal index git reads is used), and covers more keys that run a program (trailer.<name>.command, interactive.diffFilter, sendemail.sendmailCmd, toCmd, ccCmd, headerCmd and smtpServer). GIT_CONFIG_GLOBAL and similar variables that point at a file zn does not read are refused with a message that says so.
