### Security
- The hooks now check file names that a command builds when it runs, not only the ones it spells out, in every command. What the command itself fixes is worked out and checked like a typed name (a `.env` with values, a private key, a credential file, zn's own folder): a variable set earlier in the same command, a `for` loop over a fixed list, an array, `${name/x/y}` and the other `${...}` forms, `$(echo ...)` and `$(printf ...)` with known text, `read` and `xargs` fed by known text or by a list file, and `eval` or `sh -c` with known text. What it does not fix is blocked when a protected file could be behind it: a name that is partly unknown and could be a protected one (`.e$x`, `$dir/.env`, `~/.aws/$f`), a name that is entirely unknown given to a program that shows, copies or sends its files (`cat`, `sed`, `cp`, `tar`, `scp`, `source`, ...), and `eval`, `sh -c` or `trap` with code zn cannot read. A list from `find`, `ls`, `grep -l` or a file on the disk is looked up and blocked only when it holds a protected file, and everyday commands such as `git commit -m "$(...)"`, `for f in src/*.ts`, `find ... | xargs grep` and `docker run -v "$(pwd)":/app` are not affected. A program whose own name is built at run time is still not checked.
