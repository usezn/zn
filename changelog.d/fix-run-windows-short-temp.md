### Security
- `zn run` now refuses an allowed command that resolves to a file in a temp folder in two cases it missed. First, the temp folder was taken from `TMPDIR`, `TEMP` and `TMP`, which the agent can set for the command, so pointing them elsewhere let a file planted in the system temp folder run with the secret: the system temp folders (`/tmp`, `/var/tmp`, `/dev/shm`, the macOS per-user temp folders, and on Windows the temp folder of the user profile and of the system) are now always checked. Second, on Windows, a temp folder named in one form and a PATH entry in another (the long name, the short 8.3 name such as `C:\Users\LONGNA~1\AppData\Local\Temp`, a `subst` drive or a `\\?\` path) did not match. The check for files inside the project compares the same forms.
