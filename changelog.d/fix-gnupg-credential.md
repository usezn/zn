### Security
- Files in `~/.gnupg` (private keys, keyrings and trust database) are now protected like `~/.ssh/id_*` and `~/.aws/credentials`: reading them with `cat` or any other tool is refused. The folder itself is protected too (on Windows, `%APPDATA%\gnupg`): a command that names it, such as `tar`, `cp -r`, `grep -r`, `zip -r`, `rsync`, `cd` or `ls`, is refused. Only the `gpg` programs (`gpg`, `gpg2`, `gpgconf`, `gpg-agent`, `gpg-connect-agent`, `gpgsm`, `gpgv`) may use their own keyring, so `gpg --list-keys` and `gpg --homedir ~/.gnupg --list-keys` are not affected. Exporting a secret key is refused for every gpg program and keyring: `--export-secret-keys` and `--export-secret-subkeys` (also abbreviated), the `--export-secret-key-*` options of `gpgsm` and the agent's `EXPORT_KEY`. `gpg-connect-agent` is allowed only with its commands written out as arguments: a command line that runs it with a pipe, an input redirection, a `$` or backtick expansion, or an option starting with `-r` or `--r` is refused, because zn cannot see the commands it would read. Exporting a public key stays allowed.
