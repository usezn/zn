### Security
- The MCP shield (zn-gate shield) now limits what a wrapped server or a client can send it. A line over 64 MiB from the server (32 MiB from the client) is dropped before it is parsed, and messages nested more than 128 levels, with more than 4 million values, or in a batch of 1000 or more are refused. Reading from the server pauses while a lot of its output waits to be checked, so a flood cannot exhaust memory. A request waiting for its answer is never forgotten until the client cancels it: when 5000 are waiting, the next one is refused with an error instead of an old one being dropped and its answer passed on unchecked (shadow mode sends it on). When the server sends a batch that is dropped, each request it answered gets an error. `ZN_SHIELD_LIMITS` can only lower the limits. An answer that cannot be checked, is not valid JSON or is too large now gives the client a JSON-RPC error with the id of its request instead of silence, and a tool list that answers no request is not passed on.
