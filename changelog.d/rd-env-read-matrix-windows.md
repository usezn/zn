### Security
- The agent hooks: a `.env` file reached through a Windows root, a network share or an extended-length path (`type %CD%\.env`, `more \\server\share\.env`, `gc \\?\C:\ruta\.env`) is refused, because zn cannot read a path like that to check whether the file holds values, and a `.env` name is now recognised after a backslash separator on every platform. `POLICY_RULES_VERSION` is `2026-10-17.29`.
- More automated tests read a `.env` with the commands of cmd.exe and Windows PowerShell (`type`, `more`, `copy`, `findstr`, `Get-Content`, `gc`, `-Path`, `-LiteralPath`, `Select-String`) over relative, absolute and UNC paths: a `.env` with values is refused and an ordinary file is allowed in every form, on Linux and in the Windows checks job. No change beyond the refusal above.
