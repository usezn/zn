### Added
- `zn-gate evidence --export --format timesketch` (JSON Lines) and `--format timesketch-csv` write the local decision log as events that Timesketch can import as a timeline. Each event carries the hash-chain check for its record (`zn_record_hash`, `zn_prev_hash`, `zn_chain_index`, `zn_chain_verified`), so a record after a break is never shown as verified. The event message uses only the verdict, tool, agent and rule id, and the payload preview (text the agent wrote) is left out unless `--include-preview` is given. For the same log the npm and PyPI packages write the same records file, `chain.json`, `controls.md` and `README.txt`; `generator`, `pack_time_utc` (and so `manifest.json`) and, for OCSF, the package version inside each event differ.
- `zn-gate evidence --export --output FILE --manifest` also writes `FILE.manifest.json`, a short summary of the export (records, first and last time, whether the chain verified, and the file's SHA-256). `--include-preview` adds the payload preview to the Timesketch exports; it is off by default. Both packages.
- `zn-gate evidence pack --out DIR` writes a folder for auditors: the records of an optional UTC date range (`--since`, `--until`), the hash-chain check of the whole log, a summary, a plain-English control map, a manifest with file hashes and a README. `--format ocsf` writes the same records as OCSF events. The payload preview is left out unless `--include-preview` is given. Both packages.
- `zn-gate evidence --export --format ocsf` writes the decision log as OCSF events (schema 1.7.0, one Detection Finding per record), so SIEM tools that read OCSF can import it. Both packages.

### Changed
- The Python package now matches the npm package on three points: `evidence --export` exits with code 1 when the log's chain does not verify, its jsonl and csv exports write numbers and cells exactly as the npm package does, and an export printed to the screen uses plain line endings on Windows too.
- `evidence --export --manifest` never overwrites: if `FILE.manifest.json` already exists, or is a link, the command refuses before it writes anything (exit 2).
- `evidence pack` and `evidence --export --manifest` now describe the bytes they actually checked: the pack is built from one copy of the log taken at the start, so `chain.json` cannot say verified for records that were never checked even if the log changes meanwhile, and the Python manifest uses the export's own chain check instead of reading the log again. The OCSF export reads a `deny` verdict as blocked, like `block`. If the log cannot be copied, gets shorter while it is copied or is replaced meanwhile, the Python export now stops with exit code 1 and writes nothing (it says the output was not written), instead of reading the live file. The npm package streams to the output file, so after a read error it may leave an incomplete file, and it tells you not to use it.
- `evidence pack` in the Python package now copies the log the same way the export does: if the log is replaced or gets shorter while it is copied, the pack stops with exit code 1 and writes nothing. In both packages the message says the folder was not written when it was never created, and that it is incomplete only when a partial folder remains.

### Security
- The csv exports (`--format csv` and `timesketch-csv`) put a single quote in front of a cell that starts with `=`, `+`, `-` or `@` (or a tab or carriage return), so a spreadsheet program no longer runs a tool name or rule text as a formula. This also applies to the plain `csv` format that earlier versions wrote without the guard. Both packages.
