### Security
- The sensitive file rule (`path:sensitive_file`) now finds protected files written in other forms: under any directory, with Windows backslashes or drive letters, with `./`, `..` or repeated separators, behind home or working-directory variables (`$HOME`, `%USERPROFILE%`, `$env:USERPROFILE`, `~user`, `$PWD`), with quotes or escapes inside a name, or with trailing dots or spaces. It also covers more SSH private key names (`id_ecdsa`, `id_dsa`, `id_ed25519_sk`, `id_ecdsa_sk` and others). Public keys (`*.pub`) are no longer blocked. The example environment files (`.env.example`, `.env.sample`, `.env.template`) stay allowed, also when written as `./.env.example` or `dir/../.env.example`; the same name check applies to the written form and to the normalized form, so `.env`, `.env.local`, `.env.production`, `.env.dist`, `.env.example.bak` and any form that normalizes to one of them (`./.env`, `dir/../.env`, `.ENV`, `.env.` or `.env::$DATA` on Windows) stay blocked. The check reads the text only: symbolic links and Windows short names are not resolved. Node.js and Python.
