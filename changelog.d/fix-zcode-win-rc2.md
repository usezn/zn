### Fixed
- The ZCode plugin's Windows hook works from a user folder with a space, `&`, parentheses, `^` or `%` in its name, and always runs the scripts of the plugin folder: never a file of the same name in the project, also when `ZCODE_PLUGIN_ROOT` is not set.

### Security
- The ZCode plugin's Windows hook answers in time. ZCode lets a call run when its hook times out. The plugin now gives its hooks 5 minutes instead of 30 seconds, and the hook blocks the call by itself 2 minutes after ZCode started it, on both the direct Node.js path and the PowerShell one, also when zn-gate is stuck in work that never gives the launcher's timer a chance to run. Before, with the 30-second timeout, a busy computer could take longer than that to start and stop the hook, and the call ran. In our tests on a 2-CPU Windows machine with every CPU busy, ZCode timed an ordinary check at up to 131 seconds (this includes starting and ending the hook process, which a busy CPU slows down) and a stuck zn-gate, from the start of the hook until the call was blocked, at up to 154 seconds with the plugin and 181 seconds with the hooks that `zn hooks install zcode` writes; the 5-minute timeout leaves room for both. On a machine so busy that the hook takes more than 5 minutes, ZCode lets the call run. The PowerShell path no longer uses commands that Windows PowerShell has to look up in its modules, and its lookup of the program that started it has a time limit. `zn hooks install zcode` now writes the same 5-minute timeout and 2-minute deadline: run it again to update an existing install.
- When the ZCode plugin's Windows hook finds no usable Node.js, it blocks the call. It no longer takes the Windows command interpreter or another shell that started it for Node.js.
