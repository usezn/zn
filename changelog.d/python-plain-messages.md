### Changed
- Python: block messages now give a next step that fits the cause. A secret that could not be hidden says to make the tool stop returning it (it is not a false alarm), a value zn-gate cannot read says what to pass instead, and too many values says to send fewer. Rule ids are unchanged.
- Python: `@guard(on_block="return")` without a `fallback` now returns the plain block message (a string), as the framework integrations do, instead of an `Assessment` object. Code that read `.rule` or `.verdict` from that return value should use `on_block="custom"` with a `callback`, or catch `GuardBlockError`.
- Python, LangChain: when a tool returns a secret, `ZnGuardCallbackHandler` now leads with the fix (wrap the tool with `guard_langchain_tool`), and the error for `on_block='return'` is shorter and names what to use instead.
- Python: when the optional cloud check cannot run, `analyze()` now prints one short plain note to stderr per process (key rejected, plan limit reached, no answer in time, no network), and `cloud_error` is a plain sentence. The raw error shows with `DEBUG=zn`. It still falls back to the local rules. A key without `ZN_CLOUD=1`, or `ZN_CLOUD=1` without a key, now prints one note saying the cloud check is off.
- Python: clearer texts for the long-input notes of the cloud check and for the "not installed" errors of the LangChain, OpenAI Agents and Pydantic AI helpers.
