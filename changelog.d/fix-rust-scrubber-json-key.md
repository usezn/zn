### Fixed
- The Rust gateway in `src/` (experimental, not distributed) now redacts a secret in a JSON member such as `{"api_key": "<value>"}` (also with single quotes, spaces around the colon, or inside an escaped JSON string), as the Node scrubber already did. The quotes stay in the output, so redacted JSON is still valid JSON.
- The Rust gateway in `src/` (experimental, not distributed) now redacts `name="<value>"` when it sits inside a JSON string with escaped quotes, for example a shell command in a tool call.
- The Rust gateway in `src/` (experimental, not distributed) now redacts the token in `Authorization: Bearer <token>` (also Basic and Token, quoted or in a JSON member), where the header has no `=` after the name. Placeholders and short plain words are left alone.
- The Rust gateway in `src/` (experimental, not distributed) now redacts a secret value that the shell splits with quotes (`'abc''def'`) as one word, instead of leaving the second half readable.
- The Rust gateway in `src/` (experimental, not distributed) redacts two phone numbers written back to back in one pass, so scrubbing its own output changes nothing.
- The Rust gateway in `src/` (experimental, not distributed) leaves placeholders and references such as `${API_TOKEN}`, `<your-api-key>` or `********` alone in a JSON member, and only redacts a quoted value that has its closing quote at the same escape level as its opening quote, so a scrubbed JSON line stays valid JSON.
