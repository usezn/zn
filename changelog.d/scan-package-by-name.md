### Added
- `zn-gate scan --package <name>[@version]` audits an npm MCP server or skill before you add it. The package is downloaded from the registry, checked against its checksum, unpacked to a temporary folder and scanned, together with the agent-config audit: no folder is skipped by name, so `node_modules`, `dist` and `build` inside the package are scanned too. Only files with a scanned extension are read: a file with another extension, or none, is not scanned and is not listed as skipped. Before the result, the report lists what npm would run if you installed the package (its `preinstall`, `install` and `postinstall` scripts with their literal command, and its `bin` commands, and the install scripts of the dependencies it bundles); this is a note and does not change the exit code. Nothing in the package is installed or run. Exit `1` on findings, `3` when part of the package could not be read, including a file of 2 MiB or larger (it is never reported as clean, and `--allow-partial` is refused for a package), and `2` when the package cannot be fetched or is refused: a registry answer that is not JSON, a tarball address or redirect that leaves the registry's own address, a checksum that does not match, a link or special file in the tarball, or an archive that npm could read differently (data after a zero block, or an extended header with a size). It does not scan the packages the package depends on, or files of other types such as binaries.
