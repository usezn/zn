### Security
- The destructive-command check now follows a `cd` or `pushd` earlier in the same command line. After a `cd` to the home folder, the filesystem root or a system folder (`cd ~ && rm -rf .`, `cd / && find . -delete`, `pushd $HOME && rm -rf *`, `cd /etc && chmod -R 777 .`), the `.` and the relative targets are read as that folder and the command is blocked like the same command with the full path. A `cd` into a project folder (`cd build && rm -rf .`, `cd ~/projects/app && rm -rf .`) and deletes of a named subfolder (`cd ~ && rm -rf .cache`) stay allowed. A `cd` made by an earlier tool call, a folder named by a variable, and `cd -` are still not followed. The folder is tracked in one lexical pass, so a very long chain of `cd` stays fast, and a chain that builds a folder path longer than 4,096 characters is refused instead of guessed at. cmd.exe's `cd /d` and a folder written with a trailing separator (`cd C:\Windows\`) are followed too.
