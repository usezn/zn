### Security
- Python: `echo <Base64 without = padding> | base64 -d` is now decoded and checked like padded Base64, as in Node.js. Before, unpadded Base64 that hid a blocked command was allowed.
- Python: `check_tool_call`, `check_tool_result`, `@guard` and `guarded_tool` now read the strings inside dataclasses, pydantic models, other objects (through their attributes), dict views and file-system paths, as Node.js does with objects. Before, a blocked string inside any of them was allowed. A generator or other one-shot iterator is now blocked (rule `type:unscannable`), because checking it would use it up: pass a list instead. The `self` or `cls` of a guarded method is not checked. The run-context objects that agent frameworks pass to a tool (pydantic-ai `RunContext`, Google ADK `ToolContext`, OpenAI Agents SDK `ToolContext` and `RunContextWrapper`, LangChain callback managers and `RunnableConfig`) are not checked, and other application objects are read best effort, so a tool that takes them is not blocked.
- Python: `sanitize_tool_result(tool_name, content)` with a dict, list or object now checks each real string value and the JSON text, as Node.js does, and `sanitized_content` is that JSON text. Before, the text was built with `str()`, which hides BiDi and zero-width characters, so such output was marked safe.
- Python: `@guard(on_block="custom")` now raises `GuardBlockError` after the callback returns, so a blocked call never runs the function and a blocked result is never returned. `on_block="custom"` without a `callback` raises `ValueError` when the decorator is created.
- Python: `check_tool_call` and `@guard` now check argument strings longer than 256 KB in overlapping windows up to 4 MB, as tool results are, instead of only their start and end. Past 4 MB the result has `truncated=True`, and `block_truncated=True` (new in `check_tool_call`; in `@guard` it now covers arguments too) or `ZN_BLOCK_TRUNCATED=1` blocks it.
- Python: `@guard` and `guarded_tool` now check and mask the message of an exception raised by the tool, as they do its output, because agent frameworks (LangChain `handle_tool_error`, LangGraph `ToolNode`, the OpenAI Agents SDK, CrewAI) send that message to the model. A blocked message raises `GuardBlockError`; a message with a secret is raised again as an exception of the same type that carries only the masked message, without the original attached. Before, a secret or injected text in a tool error reached the model.
- Python: `@guard` now awaits, checks and masks the output of callable objects whose `__call__` is `async def` and of sync functions that return a coroutine (`guarded_tool` now does the same for the latter). Before, `check_result` and `mask_secrets` looked at the coroutine and let everything through.
- Python: with `check_result` or `mask_secrets`, the output of a tool that returns a generator or async generator is now checked and masked chunk by chunk (a blocked chunk ends the stream). Before, every chunk reached the agent unmasked, also with `guarded_tool`'s default `mask_secrets=True`. A secret split across two chunks is still not masked.
