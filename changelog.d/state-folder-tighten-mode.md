### Fixed
- zn now tightens its own state folder (`~/.zn`, or the folder `ZN_HOME` names) and its private subfolders to owner-only when they already exist with looser permissions, for example mode 0777 or with the setgid bit. `hooks install`, the hooks and `stats` all do this on Linux and macOS. A folder that belongs to another user, or one zn cannot restrict, is not used: the hook blocks the action with a message that says what to do, and the other commands stop with the same message. `zn-gate check` (npm and Python) now reports a state folder whose mode lets other accounts in.
