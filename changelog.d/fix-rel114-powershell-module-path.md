### Security
- On Windows, the PowerShell that zn starts (the vault's permission checks, the confirmation dialog, the keychain and process helpers) now gets a PSModulePath that names only the system module folder, and the permission checks and the hook scripts that zn writes for Cursor, Gemini CLI, Codex, ZCode and Antigravity use no cmdlet at all (only .NET types and operators; the ZCode launcher starts the hook with `System.Diagnostics.ProcessStartInfo`). Windows PowerShell otherwise looks in the user's own `Documents\WindowsPowerShell\Modules` first, where a module planted by the same account could replace a cmdlet such as `Get-Acl`, `Test-Path` or `Get-Command` and change what the check or the launcher reports.
