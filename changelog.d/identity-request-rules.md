### Security
- New rule family `pi:identity_request` (and `pi:identity_request_multi` for Spanish, Portuguese, French, German, Russian and Chinese) for indirect prompt injection in tool results. It flags text in a fetched page, an MCP result or a file that tells the agent to identify its user, or to put the user's name, email, account or API key in a header, a URL parameter, a cookie, a form field or the next request. Like the other heuristic injection rules it is an advisory by default (the verdict stays allow and the result carries `advisory`) and blocks in strict mode. Documentation that tells you to send your own API key in the `Authorization` header, curl examples, privacy policies, OAuth guides and form docs are not flagged. The Node.js and Python rules stay identical, and the rules version is 2026-10-23.7.
