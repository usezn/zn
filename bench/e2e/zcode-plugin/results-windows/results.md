# ZCode plugin on Windows and Linux: results on the branch

Branch `fix/zcode-plugin-windows` at e08aa22b (the plugin starts a `/bin/sh` hook and a PowerShell hook for every event). Official ZCode 3.16.3, its own headless runtime (`resources/glm/zcode.cjs`, run as the app runs it), fake local model provider, fictitious values only. The plugin is the one built from the branch (`plugins/tools/build-plugin-repo.js --target zcode`) with the published zn-gate 1.14.1 tarball (sha256 813bc6ffabd961fab9f1bd32cd71070bf34177aac4069dd8558ec3182d77c9de).

## Windows (Windows Server 2022, 3.16.3.8992)

- Installer: https://cdn-zcode.z.ai/zcode/electron/releases/3.16.3/windows-x64/ZCode-3.16.3-win-x64.exe, sha256 `B4FCCC1EAD9922D9066E083D53D3BF92BDEAC3124767D4352FD0583E5399382F`, 190777144 bytes, Authenticode signature Valid; silent install (`/S`). `zcode.cjs` sha256 `97490D0F06A7A225D54D47817ACF4B4859CDB268B59F2490CAAEDA982BEF063A` (the same file as in the Linux package); runtime zcode-cli 0.17.0.
- Node.js 22 and Python 3.12 on the VM; the run is the built-in Administrator account. The `/bin/sh` hook of every event cannot start on Windows (`spawn /bin/sh ENOENT`, outcome `failed`, 30 to 45 ms, never a block) and the PowerShell hook runs and decides.
- Result: 15 pass, 1 fail. The one failure is (e), see below.

Cause of (e), read in the code: `packages/zn-gate/lib/check.js` `unsafeStart()` (called from line 408 for each process hook of the plugin) accepts only a program whose path starts with `/`, so the absolute `C:/Windows/...` command of the new PowerShell hook is reported as "by name". It is the same on Windows and on Linux (the Linux rerun fails the same two cases). The hook itself is correct; `zn-gate check` and its test (check_zcode_windows) do not cover the plugin's PowerShell hook.

### Hook latency on Windows (h_latency, `durationMs` per hook run)

| Event | /bin/sh hook (cannot start) | PowerShell hook |
|---|---|---|
| UserPromptSubmit (first of the session) | failed, 1116 | success, 4862 |
| PreToolUse | failed, 34 and 44 | success, 763 and 747 |
| PostToolUse | failed, 30 and 32 | success, 785 and 768 |

The PowerShell hook costs about 0.75 s per call (Windows PowerShell start, Node.js start, the launcher check); the first one of a session about 1 to 5 s. The two hooks of an event run side by side.

## Linux (Debian 12 VM, app 3.16.3-8992)

- `.deb` sha256 `128132b195977fd0a8c8a6c295cf42fe159222d7a5c5efefd8b5f00ef88ab8b6`; the same 29 cases of the existing kit (`kit/e2ep.py`; only the A0 expectation changed, from 4 to 8 listed hooks).
