# zn-gate and the OWASP lists

This page shows which zn-gate features touch each category of two OWASP lists, and which categories zn-gate does not address. It also lists the agent vulnerabilities (CVEs) that `zn audit` has a rule and a test for.

Read it as a map, not as a score. A mapping shows which zn-gate feature touches a category. It is not a claim of full coverage, and it is not a certification or an assessment by OWASP. Most rows are partial: zn-gate checks text with rules on your machine, and the limits of each feature are in the page linked from its row.

The two lists:

- [OWASP Top 10 for LLM Applications 2025](https://genai.owasp.org/resource/owasp-top-10-for-llm-applications-2025/). This page maps the 2025 edition. A newer edition may exist; check the OWASP page.
- [OWASP MCP Top 10](https://owasp.org/www-project-mcp-top-10/) (project page: <https://owasp.org/projects/mcp-top-10>). It is a living document, so category names and numbers can change, and another OWASP page may name a category differently (for example MCP06). This page uses the names of the project's list as published when this page was written.

Rule ids such as `ZNA011` are the ids of [`zn audit`](audit.md#rules). Rule names such as `rm_root_home` are the rules of [destructive commands](destructive-commands.md).

## OWASP Top 10 for LLM Applications 2025

| Category | What zn-gate has for it | Not covered |
|---|---|---|
| LLM01 Prompt Injection | The local rules engine checks prompts, tool arguments, tool output and MCP tool descriptions for injection wording ([Architecture](architecture.md#three-checks-one-local-engine)). The [MCP shield](shield.md) checks tool lists, tool-call arguments and the text a server sends back, and neutralizes what carries an injection. `zn audit` reads agent instruction files for injection patterns (ZNA012), instructions to download and run code (ZNA013), to send secrets out (ZNA014) or to hide what the agent does (ZNA015), and text hidden behind blank lines (ZNA021). ZNA019 flags a CI workflow that runs an agent on text anyone can write. The hooks ask before the agent writes to its memory and instruction files ([Agent memory and instruction files](compat.md#agent-memory-and-instruction-files)). A prompt that tells the agent to put the user's identity in a request is flagged (`pi:identity_request`, [Threat model](threat-model.md#what-zn-protects-against)). | The rules match patterns, so a new phrasing can pass. Without the optional cloud check there is no classifier ([README](../README.md)). zn-gate does not stop the model from following an instruction it did not flag. |
| LLM02 Sensitive Information Disclosure | The scrubber replaces secrets and personal data in tool output, tool arguments and MCP results before the model sees them ([Architecture](architecture.md#three-checks-one-local-engine)). The vault keeps real values out of the context and `zn run` gives a value only to a command you approved ([Keep secrets out of your agent](secrets.md)). Reads of `.env` files with real values and of credential files are blocked ([Threat model](threat-model.md#what-zn-protects-against)). A network request that carries personal data or a literal secret asks you first ([Network requests that carry personal data](egress-check.md)). `zn audit` finds secrets written in agent configs (ZNA011) and instructions that send secrets out (ZNA014). | Secrets with no known format under an innocent name. Values inside a program you allowed in env mode. A value built at run time. Antigravity and ZCode hooks cannot rewrite tool output. See [What zn does not protect against](threat-model.md#what-zn-does-not-protect-against) and [compat.md](compat.md). |
| LLM03 Supply Chain | `zn audit` flags MCP servers and plugins that are not pinned (ZNA005), plugin marketplaces and enabled plugins in project settings (ZNA017), servers loaded from a URL (ZNA006) and project MCP servers that start a local command (ZNA003). The shield remembers a fingerprint of each tool and flags a tool that changes or appears later; in `block` mode it removes the tool ([Tool pinning](shield.md#tool-pinning)). | zn-gate does not read or resolve packages, so a pinned package can still be malicious ([audit limitations](audit.md#limitations)). It does not check models, datasets or your application's dependencies. |
| LLM04 Data and Model Poisoning | None. | zn-gate does not look at training data, fine-tuning data or model weights. |
| LLM05 Improper Output Handling | Partial. The hooks can refuse shell commands the model writes when they have the shape of a wipe of the machine: `rm_root_home` and `disk_overwrite` are on by default, four more rules are off by default ([Destructive commands](destructive-commands.md)). Network requests the agent writes are read before they run ([egress check](egress-check.md)). | zn-gate does not validate model output before another system uses it, and `check_tool_call` does not judge whether a command or a query is destructive ([Architecture](architecture.md#three-checks-one-local-engine)). The destructive-command rules read command text only and miss paths built at run time, scripts saved and run later, and commands inside containers ([What it does not do](destructive-commands.md#what-it-does-not-do)). |
| LLM06 Excessive Agency | `zn audit` flags broad permissions such as `Bash(*)` and `bypassPermissions` (ZNA010), MCP servers approved in advance (ZNA004), hooks and `statusLine` commands that run on their own (ZNA001), download-and-run commands (ZNA002) and credential helper commands (ZNA009). First use of a command for a secret and a wider secret policy are confirmed on the vault's own channel ([Threat model](threat-model.md#what-zn-protects-against)). `zn run` gives secrets only to approved commands, and approvals are bound to the executable's real path and file identity. The [destructive-command rules](destructive-commands.md) and the [egress check](egress-check.md) ask or refuse before specific commands. | zn-gate is not a sandbox. It does not limit what a tool you allowed can do, or what an authorised credential can be used for ([What zn does not protect against](threat-model.md#what-zn-does-not-protect-against)). |
| LLM07 System Prompt Leakage | None as a feature. Related: secret values are kept out of the model's context, so they are not there to be repeated ([Threat model](threat-model.md#what-zn-protects-against)). | zn-gate does not detect a request to reveal a system prompt as such, and does not protect other content of a system prompt. |
| LLM08 Vector and Embedding Weaknesses | None. | zn-gate does not look at vector stores or embeddings. |
| LLM09 Misinformation | None. | zn-gate does not judge whether model output is true. |
| LLM10 Unbounded Consumption | None. | zn-gate does not limit tokens, requests or cost. |

## OWASP MCP Top 10

| Category | What zn-gate has for it | Not covered |
|---|---|---|
| MCP01 Token Mismanagement and Secret Exposure | `zn audit` and `zn scan` find keys written in MCP server configs and never print the value (ZNA011); the fix is to keep the value in the vault and start the server through `zn run` ([MCP server configs](secrets.md#mcp-server-configs)). The vault, markers and `zn run` keep values out of the model's context; `zn run` refuses a marker written in a command's arguments ([Threat model](threat-model.md#what-zn-protects-against)). The shield redacts secrets in tool output ([Shield](shield.md)). `zn audit` flags credential helper commands in project settings (ZNA009). | Token lifetime, rotation and scoping at the server. A program running as your user can still read a value you gave it ([Where the value lives while a program runs](threat-model.md#where-the-value-lives-while-a-program-runs)). |
| MCP02 Privilege Escalation via Scope Creep | `zn audit` flags broad permissions (ZNA010) and MCP servers approved in advance (ZNA004). The shield flags a tool that is new or changed after you started using the server ([Tool pinning](shield.md#tool-pinning)); approving a change is refused when it comes from an AI agent ([Approve a change](shield.md#approve-a-change)). | The scopes a server grants to its own tokens. |
| MCP03 Tool Poisoning | The shield neutralizes hidden instructions in tool and parameter descriptions, checks the other text a server sends, and pins each tool by a SHA-256 fingerprint of its whole definition so a later change is flagged ([Shield](shield.md), [Tool pinning](shield.md#tool-pinning)). The first list a server returns is trusted as it is. | A tool that is poisoned from its first list. Servers that are not wrapped by the shield, and remote (URL) servers, which the shield cannot wrap ([Shield](shield.md#wrap-all-your-servers-at-once-init---wrap-mcp)). |
| MCP04 Software Supply Chain Attacks and Dependency Tampering | `zn audit` flags unpinned MCP servers and plugins (ZNA005), plugin marketplaces (ZNA017) and servers loaded from a URL (ZNA006). Pins follow the server's command line, so a new package version is a new server whose first list is trusted again ([Tool pinning](shield.md#what-gets-pinned)). | zn-gate does not resolve packages or check them for known vulnerabilities, and a pinned package can still be malicious ([audit limitations](audit.md#limitations)). |
| MCP05 Command Injection and Execution | `zn audit` flags a project MCP server that starts a local command (ZNA003), commands that run automatically (ZNA001) and downloads that are run unread (ZNA002). The hooks can refuse shell commands that wipe a machine ([Destructive commands](destructive-commands.md)). | zn-gate does not check the code a server runs, or how a server builds a command from its inputs. |
| MCP06 Prompt Injection via Contextual Payloads | The shield checks tool output, notifications, sampling requests, resource and prompt contents, error messages and structured content, and replaces output that carries an injection with a short notice ([Shield](shield.md)). `check_tool_result` does the same for tool output outside the shield ([Architecture](architecture.md#three-checks-one-local-engine)). | Pattern-based, so a new phrasing can pass. In shadow mode, output is only recorded ([Shadow mode](shield.md#shadow-mode-log-without-blocking)). |
| MCP07 Insufficient Authentication and Authorization | Only transport: `zn audit` flags a remote MCP server (medium for plain `http`, low for `https` in a project) (ZNA006). | zn-gate does not check whether a server authenticates or authorizes its callers. |
| MCP08 Lack of Audit and Telemetry | Every assessment is recorded in a local hash-chained decision log, and the shield records each decision ([Architecture](architecture.md#three-checks-one-local-engine), [Shield](shield.md)). The vault keeps an audit log whose chain is verified before it is shown, exported or uploaded ([Threat model](threat-model.md#what-zn-protects-against)); it can be exported as OpenTelemetry logs ([Export the audit log](team.md#export-the-audit-log-to-opentelemetry)). | The logs describe what zn-gate saw. They do not replace the audit log of an MCP server. They detect accidental or partial edits and are not tamper-proof against someone who can write the files ([README](../README.md)). |
| MCP09 Shadow MCP Servers | `zn reach` lists the MCP servers your agents are set up to run, and `zn audit` reports project MCP servers, unpinned ones and remote ones ([Reach](reach.md)). `init --wrap-mcp` finds the servers in your agents' configuration files ([Shield](shield.md#wrap-all-your-servers-at-once-init---wrap-mcp)). | They read the configuration files of the supported agents on one machine. They do not find a server that is not configured there, and they do not discover servers across an organization. |
| MCP10 Context Injection and Over-Sharing | Network requests that carry personal data or a literal secret ask you first ([Egress check](egress-check.md)). The scrubber replaces personal data and secrets in tool output and arguments before the model sees them ([Architecture](architecture.md#three-checks-one-local-engine)). | zn-gate does not separate context between users or sessions, and does not limit what an MCP server may read from context you gave the agent. |

## Agent vulnerabilities `zn audit` covers

[`zn audit`](audit.md) reads a repository's agent configuration without running anything. Each case below has a rule and a test in the zn-gate package that builds the repository layout and checks that the rule reports it.

| CVE | Agent and what the repository held | Rules that report it |
|---|---|---|
| CVE-2026-21852 | Claude Code before 2.0.65: a project settings file set `ANTHROPIC_BASE_URL` to another server | ZNA007 |
| CVE-2026-12957 | Amazon Q Developer: `.amazonq/mcp.json` started a command when the project opened | ZNA003 (and ZNA002 when the command downloads and runs a script) |
| CVE-2025-61260 | Codex CLI 0.23.0 and earlier: project `.env` and `.codex/config.toml` MCP servers were loaded without confirmation | ZNA003 for the MCP server, ZNA007 for an endpoint set in `.env`, ZNA005 when the server is not pinned. ZNA008 covers environment variables that load code or certificates |
| CVE-2026-48124 | Cursor before 3.0.0: hooks in `.claude/settings.local.json` ran without approval | ZNA001 |
| CVE-2026-63093 | Cursor for Windows: a `git.exe` in the repository root was run on start | ZNA016 |

What this means and does not mean:

- The rules report the files that the bug acted on. They do not detect which version of an agent you run, and they do not fix the agent. Updating the agent fixes the bug; the files stay in the repository ([audit.md](audit.md)).
- The rules read files. They do not run them, so a hook that calls a local script is reported as a hook and not judged by what the script does ([audit limitations](audit.md#limitations)).
- Separately from `zn audit`, the local rules engine normalizes bidirectional-override characters in text it checks, the technique of CVE-2021-42574 (Trojan Source), and blocks a prompt that uses one (`evasion:bidi_override`).

## What to do with this

- To see what applies to your repository, run `zn audit` on it ([Audit](audit.md)) and `zn reach` on your machine ([Reach](reach.md)).
- To run the audit on every pull request, see the [GitHub Action](github-action.md).
- For the full list of what zn-gate does not protect against, read the [Threat model](threat-model.md).
