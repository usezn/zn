# Security Advisory: SEC-2026-02

**Title:** Insufficient session and token revocation on password reset (CWE-613)  
**Date:** 2026-09-30  
**Severity:** Medium (CVSS: 6.5 / CVSS:3.1/AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:N/A:N)  
**Vulnerability Type:** Insufficient Session Expiration (CWE-613)  
**Remediation:** Fixed in the usezn.com platform, which is not part of this repository  
**Reported by:** [Ganesh RK](https://www.linkedin.com/in/ganesh-rk-6b827828a/)  

---

## Summary

A session management gap was identified wherein resetting or changing an account password in `usezn.com` did not immediately revoke pre-existing authorization grants, refresh tokens, or active sessions on concurrent devices or alternate browsers. Consequently, an existing browser session retained valid refresh tokens and could continue accessing API resources until the refresh token expired naturally.

---

## Impact

If an account credential was compromised or a user initiated a credential reset after suspected unauthorized access, an attacker with a pre-existing authenticated session could maintain unauthorized access despite the password reset.

---

## Remediation

The issue was remediated with a multi-layered session invalidation architecture:

1. **Server-Side Token Revocation:** Upon password change or reset, Auth0 triggers and backend handlers now immediately invoke the Management API to revoke all active grants and refresh tokens (`DELETE /api/v2/grants`, `revokeRefreshToken`) for the target user ID.
2. **Client-Side Session Termination:** When a user completes a password update, all active local session tokens are purged, and existing browser contexts are redirected to sign-in.
3. **Reduced Access Token Lifetimes:** Default access token lifetimes were reduced to 1 hour across all client applications so existing in-flight tokens expire quickly.
4. **Automated Verification:** Verified via multi-browser concurrent sessions that changing a password in one browser immediately causes any subsequent refresh attempt in another browser to fail with HTTP 401/403.
