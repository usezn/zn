# How this plugin is built and checked

This repository is generated by the release workflow of [usezn/zn](https://github.com/usezn/zn) with `plugins/tools/build-plugin-repo.js`, and each release reaches `main` through a pull request. Nothing here is edited by hand.

For a release `X.Y.Z` (the `version` in `.claude-plugin/plugin.json`), you can check it yourself with Node.js and the GitHub CLI (version 2.49 or later, for `gh attestation`):

1. Download the published package and check its integrity and provenance:

   ```
   npm pack zn-gate@X.Y.Z
   gh attestation verify zn-gate-X.Y.Z.tgz --repo usezn/zn
   ```

   The sha512 integrity of the file must match `integrity` in `scripts/zn-gate.lock.json` and `npm view zn-gate@X.Y.Z dist.integrity`.

2. Unpack it and compare it with `vendor/zn-gate`: every file in `vendor/zn-gate` must be identical to the file with the same path under `package/`. The only files of the package that are left out are TypeScript sources and declarations (`.ts`, `.mts`, `.cts`) and source maps (`.map`).

3. Every SHA-256 in `scripts/zn-gate.lock.json` must match its file in `vendor/zn-gate`, and no other file may be there.

4. Every other file, except `scripts/zn-gate.lock.json` (step 3) and `.gitattributes`, must be identical to the file in [usezn/zn](https://github.com/usezn/zn) at the tag `vX.Y.Z`: `.claude-plugin/plugin.json`, `.mcp.json`, `hooks/hooks.json`, `icon.png`, `LICENSE`, `scripts/zn-launch.js` and `skills/` from `plugins/zn-gate/`, and `README.md`, `SECURITY.md` and `PROVENANCE.md` from `plugins/claude-dir/`. `.gitattributes` contains only `* -text`, which keeps Git from changing line endings on checkout.

Each release pull request is checked this way before it is merged into `main`.
